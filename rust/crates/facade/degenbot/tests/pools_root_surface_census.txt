# ADR-084 W5 (phase 1, W5b) — the degenbot-pools root surface after the
# namespacing execution. The 34 former root modules (33 pre-W2 + `affected`)
# moved under the four capability modules recorded in the phase-0 snapshot;
# this file now pins the EXECUTED state.
#
# The pin is review-required: `architecture_gates.rs::pools_root_surface_is_pinned`
# fails when a module is added, removed, or re-homed without a review of this
# file, and the root `pub` name count (1011) is asserted so untracked surface
# growth fails loudly. The tick-word merge policy (the `sim::tick_fetch`
# capability's `policy` half) is the review that moved 966 -> 1012: every new
# door name has a named consumer outside the capability crate (substrate, bot,
# or the rpc fixtures), and the helper fns only the crate itself calls stayed
# `pub(crate)`. The 1012 -> 1014 review is the engine's typed view reads: the
# `V2_RESERVES_SLOT` row joins the slot-layout door (the simulation engine's
# reserves read addresses the slot by name instead of re-owning the literal)
# and `ConcentratedLiquiditySlotLayout::slot0_slot` is the fork's slot0 word-0
# accessor that read path calls — both consumed by `degenbot-simulation`.
# The 1014 -> 1011 review is the wide-integer relocation: `isqrt_u512`,
# `isqrt_u2048`, and `narrow_u512_to_u256` are Newton-iteration arithmetic, not
# pools surface, and now live in `degenbot-math::bigint`, which the Möbius
# solve modules import. The three left the door with no pools-side replacement:
# a shade wider than U256 is a `degenbot-math` concern, not a pool family one.
# The 1028 -> 1029 review is the phantom-parity rig's path sim:
# `ConcentratedLiquidityPathSim` joins the concentrated-liquidity door so the
# degenbot-simulation phantom-fidelity rig names the path-level sim at the
# root (ADR-084 D2), its only out-of-crate consumer.
# The 1029 -> 1038 review is the walk-census vocabulary: the V4 projection
# fix's `RangeExitKind` / `SwapWalkCensus` (and their accessors) plus
# `ConcentratedLiquidityPathOutcome` — the per-hop crossed-ticks /
# bitmap-words census the gas model consumes, consumed by the gas
# decomposition harness and the admission floor's crossing counts.
# The 1053 -> 1073 review is the recorded hook charge (F2): the
# `state::v4_hook_fee` vocabulary (HookFeeRecord / HookFeeReading /
# charge_is_hook_carried / direction_slot / the refresh constant and
# accessors) — the search-time fee record for hook-carried-charge pools,
# consumed by the admission floor, the re-quote plan, and registration.
# The count is per NAME, not per statement (the previous
# granularity pinned 681 statements): a `pub fn`/`struct`/`enum`/`trait`/
# `const`/`type`/`mod` declaration counts once, and a `pub use` counts one per
# re-exported name, so a name added to an existing `pub use a::b::{X, Y}` block
# moves the pin exactly as a new `pub fn` does.
#
# The root's `pub use` blocks ARE the door: the four capability modules hold
# the trees, and every name a consumer may write at the crate root is one of
# these re-exports. Repointing a consumer off an implementation module and onto
# the door therefore grows this surface by one name per new door item, and the
# pin is bumped in the same change.
#
# The 1017 -> 1027 review is the trust-flag vocabulary's move DOWN a layer:
# `Caveats` (ADR-037 D4's additive flag set) leaves `degenbot-substrate`'s
# swap-simulation module for `sim::caveats`, the crate that owns both outcome
# shapes it flags — the stateless swap outcomes and the solve results — so a
# sparse-coverage solve result can carry the same vocabulary as a sparse-
# coverage swap read. Substrate re-exports the type, so its public module path
# is unchanged; the 10 names are the relocated type (struct + two consts + four
# accessors), its module, the root re-export, and `PoolEntry::tick_coverage`
# (the resolve loop's per-hop registration-coverage read).
#
# The 1027 -> 1028 review is ADR-090 H3's caveat lift: `Caveats::without` is
# the one legitimate AND-NOT on the trust-flag set — a flag that described a
# TIER rather than a pool stops applying when a later tier answered exactly
# (`HOOKED_POOL` lifts off a V4 leg the finalist re-quote priced black-box at
# the anchor). The consumer outside the capability crate is the bot's clamp
# (`solve_cycle::merge`), which is the seam that owns the solve result the flag
# rides on; `union`'s existing set-construction API cannot express a removal,
# and a registration-time fact such as `SPARSE_COVERAGE` never lifts.
#
# The 1075 -> 1074 review is the capability-label retirement:
# `state::capability::Family::label()` is gone. It was a second kebab label
# table over the capability axis (`"solidly-stable"`, `"curve-stableswap"`,
# `"lfj-binned"`), and its only readers were assertion messages in this crate
# and in `degenbot-strategy`'s family test. Those messages now render the
# variant's `Debug` name, so the registry's `RegisteredPoolFamily::tag()`
# remains the ONE kebab family vocabulary (ADR-059 D1).
#
# The 1074 -> 1076 -> 1075 review is the fee-typing chunk. The +2 was
# `state::spec_bounds::validate_stable_swap_fee` (declaration + door name),
# which applied the solidly-stable zero-gamma bound at registration; the type
# now enforces it (`FeeRatio` refuses a zero retained gamma at construction),
# so the validator retired (-2) and the registration door's re-check with it.
# The +1 is the `DexVariant` re-export at the root: it is the type of
# `RegisterV2PoolParams::variant` / `V2PoolIdentity::variant`, so a consumer
# holding those params can name it without an extra edge on the preset crate
# (`degenbot-strategy`'s fixtures are that consumer).
#

# plus the name count from `count_pub_items` in the gate.
