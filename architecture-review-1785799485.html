Problem — Four probe/verify modules each diff engine state against on-chain truth at a different seam, each with its own mismatch type and its own stop/panic reaction; the failure class is still decoded by hand — the live [sim-revert-swap] matched=false line from the fee-1 sessions only says predicted > actual, not why.

Solution — Extract one tripwire seam producing a typed verdict; the probes converge behind it, and the loop keeps only the trip and the exit, none of the classification noise.

Wins

  • Root-causing lives in one place (locality)
  • One verdict type across all probes
  • Class is named the moment it trips
  • Classification is a pure function — unit-testable
Refines ADR-021, does not re-litigate it — ADR-021 settles the posture (detect, classify, stop loudly, never heal) and explicitly names "a single discriminating tripwire module" as the intended shape with "the extracting is the work." This candidate does that extraction; it never touches the forbidden auto-repair path.

Problem — The delivery FSM and the recovery heuristics (watchdogs, anchor reset, late-forward, backfill resets) are tangled in one giant async loop; every live-session failure class so far produced a fresh inline patch in the same loop, so the recovery knowledge has no locality.

Solution — Split delivery ("what happened") from a narrow recovery seam: a DeliveryPolicy adapter that, given a typed anomaly (HeaderStall / LogSilence / LateForward), returns a decision against a small action interface.

Wins

  • Recovery policy concentrates in one module
  • New failure class = one new policy arm
  • Policy driven by a fake sink in milliseconds
  • Wedging/backlog classes become unit tests
Was surfaced in the prior review (2026-08-02) as the top delivery recommendation and is still open — the loop is now larger, not smaller. Refines ADR-008 (Edge-B backfill) and explicitly reconciles dropped WS logs only; it never re-syncs scalar pool state, so it does not conflict with the Candidate 1 tripwire posture.

Problem — The sharpest invariant of the new two-stamp state model — "apply_swap advances both clocks; apply_liquidity_update advances liquidity always and the price only for an in-range post-seed event; replace_tick_data advances liquidity only; backfill replay is the sanctioned exception" — is re-encoded inside both the V3 and V4 mutator adapters, with no single site owning the decision.

Solution — Center the attribution decision in one small pure helper behind the existing ConcentratedLiquidityPoolMut seam; the adapters call it instead of re-writing it.

Wins

  • The rule is tested exactly once
  • V3 and V4 adapters cannot drift apart
  • Deleting an advance call can't silently break it
  • Attribution is table-driven and unit-testable
Refines ADR-014/ADR-017 CL trait discipline, does not re-litigate it — the CL family trait with V3+V4 adapters stands; this only stops the adapter bodies from re-encoding the same subtle rule twice. Marked Worth exploring because the two-stamp design (OB7UNY) is freshly landed and still settling.

Top recommendation

Start with Candidate 1 — the state-accuracy tripwire

It is the smallest, highest-leverage open move, and its design intent is already settled: ADR-021 fixed the posture (fail-fast, stop-only, never auto-repair), so extracting the discriminating module is pure win with no decision to re-open. It also targets the single most-recurring live failure class — the fee-1 / desync sessions whose matched=false event still forces hand-archaeology to name the defect. Candidate 2 stands apart as a pure delivery-recovery seam (it reconciles dropped WS logs, never scalar state, so it cannot collide with the tripwire); Candidate 3 is the newest but smallest, and is better revisited once the two-stamp model has settled.
