## Summary
The new cmd_executor's `execute()` accepts a second parameter `expected_balance: uint256` that replaces the SKIP_PROFIT_CHECK preamble command. This packed value contains a check_mode (upper 8 bits) and expected_value (lower 248 bits). The bot must compute pre-tx balance, pack it with the correct mode, and pass it as the second argument.

## Contract ABI Change

```python
EXECUTOR_ABI = [
    {
        "stateMutability": "payable",
        "type": "function",
        "name": "execute",
        "inputs": [
            {"name": "commands", "type": "bytes"},
            {"name": "expected_balance", "type": "uint256"},  # NEW
        ],
        "outputs": [
            {"name": "", "type": "uint256"},
        ],
    },
]
```

## Packed expected_balance Format

```
expected_balance = (check_mode << 248) | expected_value
```

| check_mode | Check Performed | Use Case |
|------------|----------------|----------|
| 0 | Skip (no check) | `expected_balance=0` — off-chain verification only |
| 1 | `WETH.balanceOf(self) + self.balance >= value` | Default for V2/V3/V4+other paths |
| 2 | `PM.balanceOf(self, weth_id) >= value` | V4V4V4 with V4_MINT_COMPACT profit capture |

## Changes Required

### 1. Update EXECUTOR_ABI
Add `expected_balance: uint256` as the second parameter.

### 2. Remove SKIP_PROFIT_CHECK from preamble
In `enc_preamble()`, the `skip_profit` parameter should default to False (or be removed). The SKIP_PROFIT_CHECK opcode still works but should not be the default — the on-chain profit check is the contract's primary safety mechanism.

### 3. Compute and encode expected_balance in simulate_one()
```python
# Before simulation:
# Call 1: WETH.balanceOf(executor)
# Call 2: ETH balance of executor
# Call 3: PM.balanceOf(executor, weth_erc6909_id)

# For most paths (mode 1):
pre_tx_combined = weth_before + eth_before
expected_balance = (1 << 248) | pre_tx_combined

# For V4V4V4 with V4_MINT (mode 2):
expected_balance = (2 << 248) | erc6909_before
```

### 4. Update simulation pattern
The current 7-call simulation pattern can be simplified:
- Keep pre-tx balance reads (3 calls)
- execute(commands, expected_balance) with the packed value
- Keep post-tx balance reads (3 calls) for off-chain profit measurement
- The on-chain profit check already ensures the transaction reverts if unprofitable

### 5. Pass expected_balance through dispatch pipeline
The `dispatch_profitable_results()` and `simulate_one()` functions need the pre-tx balance values. These should be fetched once per dispatch and reused.
