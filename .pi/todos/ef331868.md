## Problem

All 3-hop V4 paths (V4-V4-V4, V4-V3-V4, etc.) fail simulation with `CurrencyNotSettled()`. Root cause: solver-estimated hop outputs used in `enc_v4_swap_compact()` differ by ±1 wei from the actual PoolManager delta after preceding swaps due to V4 rounding.

## Fix Applied

Replaced `enc_v4_swap_compact(amount=...)` with `enc_v4_swap_dynamic()` for all subsequent V4 hops, and switched profit takes to `enc_v4_take_delta()` with `enc_v4_settle_all()` to catch residuals.

### Changed functions in `examples/eth_backrun_helpers.py`

- `_3hop_v4_v4_v4`: swap B & C → dynamic; profit → take_delta; settle_delta → settle_all
- `_3hop_v4_v4_v3`: swap B → dynamic; settle_delta → settle_all
- `_3hop_v4_v4_v2`: swap B → dynamic; settle_delta → settle_all
- `_3hop_v2_v4_v4`: swap C → dynamic; profit → take_delta; added settle_all
- `_3hop_v3_v4_v4`: swap C → dynamic; profit → take_delta; added settle_all

## Verification (live bot `/tmp/bot-run-dynamic.log`)

- **V4-V4-V4**: no longer fails with `CurrencyNotSettled()`. Now fails with `V4_TAKE_DELTA: non-positive delta` when the path is unprofitable (WETH delta ≤ 0). This is correct behavior — the encoding bug is fixed; the solver is just finding no profitable V4-V4-V4 paths right now.
- **V4-V3-V4**: still fails with `CurrencyNotSettled()`. This is a **separate structural bug**: the V3 callback delivers forward tokens to the executor, but `_3hop_v4_v3_v4` never transfers them into the PM before the V4c swap. Dynamic amounts alone cannot fix this.
- **Suppression works**: paths with 10 consecutive failures are now being suppressed correctly.

## Remaining issue (separate from dynamic-swap fix)

- `_3hop_v4_v3_v4` and `_3hop_v3_v4_v4` need structural callback fixes: `sync + erc20_transfer + settle` to move V3 output into PM before V4c swap. These are NOT V4→V4 chains and cannot use `V4_SWAP_DYNAMIC` for the intermediate-to-V4 hop.
