## Permutation Verification Procedure

For each of the 27 permutations, run exactly this process:

### Step 1: Set the permutation filter

Edit `PATH_PERMUTATION_FILTER` in `examples/eth_backrun_v2_v3_v4_rust.py` to isolate one permutation:

```python
PATH_PERMUTATION_FILTER: set[str] | None = {"V2-V3-V4"}  # one permutation at a time
```

This automatically:
- Loads only the required pool table types into the graph (via `_pool_types_from_filter`)
- Prunes DFS edges at each hop to enforce the permutation ordering (via `pool_type_per_depth`)

### Step 2: Restart the bot detached, capturing output to a log file

```bash
cd ~/code/degenbot
nohup uv run python examples/eth_backrun_v2_v3_v4_rust.py \
  > logs/perm-V2-V3-V4.log 2>&1 &
echo $! > logs/perm-V2-V3-V4.pid
```

### Step 3: Observe for 15 minutes

Wait 15 minutes for sufficient blocks and simulation data. The bot will:
- Build paths matching only this permutation
- Solve them via the Rust engine
- Simulate profitable candidates via `eth_simulateV1`
- Log outcomes under `[sim]` (summary) and `[sim-fail]` (individual failures)

### Step 4: Report simulatability percentage

After 15 minutes, extract the results from the log:

```bash
# Total simulation candidates (from [sim] lines)
TOTAL=$(grep -c '\[sim\]' logs/perm-V2-V3-V4.log || echo 0)

# Successful simulations (gross profit > 0 = onchain-executable)
OK=$(grep '\[sim\]' logs/perm-V2-V3-V4.log | grep -oP '\d+ ok' | grep -oP '\d+' | paste -sd+ | bc || echo 0)

# Failed simulations (revert on simulation = encoding bug or on-chain state mismatch)
FAIL=$(grep '\[sim\]' logs/perm-V2-V3-V4.log | grep -oP '\d+ failed' | grep -oP '\d+' | paste -sd+ | bc || echo 0)

# Calculate simulatability rate
echo "Permutation V2-V3-V4: $OK ok / $TOTAL candidates ($(( OK * 100 / (OK + FAIL) ))% simulatable)"
```

A simulation that completes with a result (gross profit > 0 or even gross profit = 0 but no revert) counts as **onchain-executable** — the encoding is correct. A simulation that reverts counts as a **failure** — the encoding is wrong or the on-chain state doesn't match the solver's assumption. We don't require profit, only that the swap could execute onchain.

### Step 5: Classify and record

For each permutation, record:

| # | Permutation | Candidates | Simulatable | % | Classification | Failure modes |
|---|-------------|-----------|-------------|---|----------------|---------------|
| 1 | V2-V2-V2 | | | | ✅/⚠️/❌ | |

Classification:
- ✅ **Passing** — ≥80% simulatable. Remaining failures are tax-token reverts, liquidity edge cases, or rounding residuals.
- ⚠️ **Partial** — 20–79% simulatable. Some encoding bugs mixed with tax-token/liquidity failures.
- ❌ **Broken** — <20% simulatable. Encoding bug confirmed. Must debug and fix before re-testing.

### Step 6: Debug and fix broken/partial encoders

For ❌ and ⚠️ permutations:

1. Examine `[sim-fail]` lines for the revert reason (decoded selector, error string)
2. For V4 reverts: use `debug_traceCall` output (already logged at DEBUG level for V4-hybrid paths)
3. Cross-reference with the encoder function in `eth_backrun_helpers.py`
4. Compare against the contract test patterns in `~/code/executor/tests/`
5. Fix the encoder, re-test that single permutation
6. If the fix affects shared code (e.g., `enc_v4_settle_all`, `enc_v3_swap_compact`), re-test permutations that use that shared code

### Step 7: Kill the bot process and proceed to the next permutation

```bash
kill $(cat logs/perm-V2-V3-V4.pid)
```

Return to Step 1 with the next permutation.
