## Method

1. Set `PATH_PERMUTATION_FILTER` to a single permutation (e.g. `{"V3-V4-V3"}`)
2. Run the bot, let it build paths and simulate for ~5 minutes
3. Record the results from `[sim]` log lines:
   - Total candidates, ok count, failed count
   - Failure types (from `[sim-fail]` with `tokens=` diagnostic)
4. Categorize each permutation:
   - ✅ Passing (high success rate, failures are tax-token or liquidity)
   - ⚠️ Partial (some encoding bugs, some tax tokens)
   - ❌ Broken (all failures, encoding bug confirmed)
5. For broken/partial, debug the encoder and fix
6. Re-test after fixes

## Known issues

- V3-V4-V3: all `Uni::_transferTokens: transfer amount exceeds balance` — ~0% success. Likely tax-token (0x1f9840 = UNI) but could also have encoder bugs. Need to test with non-tax-token paths specifically.
- V2 pools are currently commented out in `pool_types` — need to re-enable `UniswapV2PoolTable` for V2 permutations.

- V2 pool building via `bot.build_pool()` requires the init hash to be known.
- `_concrete_pool_types` correctly expands abstract bases for the filter.
