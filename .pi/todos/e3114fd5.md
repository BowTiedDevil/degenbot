## Problem
V4→V2 paths revert with INSUFFICIENT_LIQUIDITY — V2 pools can't fulfill the swap amounts.

## Resolution
Contract test `test_v4_v2_weth_usdc_to_weth` passes, confirming the encoding is correct. The `_zero_intermediate_deltas` logic in unlockCallback Phase 2 properly zeroes forward token deltas after take/transfer payloads. The wrong `amount_out` bug was already fixed (V2 amount_out = weth_out, not forward_out).

Some V4→V2 paths on mainnet may still fail with INSUFFICIENT_LIQUIDITY if the V2 pool genuinely lacks reserves — this is a market condition, not a code bug.

## Status: RESOLVED by contract update + encoder improvements. Mainnet failures are market-conditional, not code bugs.
