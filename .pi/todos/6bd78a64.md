## Summary
Replace V4_TAKE (32-byte amount) with V4_TAKE_COMPACT (12-byte uint96 amount) in all path encoders. Saves 20 bytes per take with zero gas overhead. All practical token amounts fit in uint96 (max ~7.9×10²⁸).

## Changes in eth_backrun_helpers.py
Search for all `enc_v4_take(` calls and replace with `enc_v4_take_compact(` where the amount is a known value (not read from PM delta).

### Pattern
```python
# Old:
inner += enc_v4_take(forward_idx, executor_idx, forward_out)  # 35 bytes

# New:
inner += enc_v4_take_compact(forward_idx, executor_idx, forward_out)  # 15 bytes
```

### Where V4_TAKE_DELTA is already correct
`enc_v4_take_delta()` (3 bytes) is already more compact and should be kept where the amount can be read from PM exttload. V4_TAKE_COMPACT is for cases where we have an explicit amount but V4_TAKE_DELTA isn't usable (delta not available or already consumed).

### When to use each
| Command | Size | When to Use |
|---------|------|-------------|
| V4_TAKE | 35 bytes | Never — always prefer compact or delta |
| V4_TAKE_COMPACT | 15 bytes | Known amount, delta not available |
| V4_TAKE_DELTA | 3 bytes | Take entire positive delta (no amount needed) |

### Affected Encoders
- `_encode_cmd_v4_v4()` (WETH→executor takes)
- `_encode_cmd_v4_v3()` (WETH→executor takes)
- `_encode_cmd_v3_v4()` (output→executor takes)
- `_encode_cmd_v4_v2()` (forward→V2 takes)
- `_encode_cmd_v2_v4()` (output→executor takes)
- All 3-hop encoders with V4_TAKE calls (~15 encoders)

### Note on WETH_DEPOSIT/WETH_WITHDRAW
These 33-byte commands could also benefit from compact variants (WETH_DEPOSIT_ALL=1 byte, WETH_WITHDRAW_ALL=1 byte), but they are used with specific amounts, not entire balances. Leave as-is unless the amount equals the executor's entire WETH/ETH balance.
