## Problem

The Rust pump buffers all WS logs in `pending_logs` until a `newHeads` header arrives, creating a 1-block (~12s) latency before events are visible to the solver. This makes the arbitrage bot uncompetitive.

## Design

### Sub-engines: return affected pool keys from individual `apply_*` methods

- `V2BlockEngine::apply_sync` → `Option<u64>`
- `V3BlockEngine::apply_swap` → `Option<u64>`
- `V3BlockEngine::apply_liquidity_update` → `Option<u64>`
- `V4BlockEngine::apply_swap` → `Option<(u64, u64)>`
- `V4BlockEngine::apply_liquidity_update` → `Option<(u64, u64)>`

### Top-level UniswapEngine: split into `apply_log` + `solve_dirty`

- `apply_log(log, block_number)` — decode, apply to sub-engine, return affected path IDs via `pool_to_paths` reverse index
- `solve_dirty(block_number, metadata)` — expire buffered events, rebuild+solve affected paths, compute diff, send batch
- `process_block` rewritten as `apply_log × N + solve_dirty` for backward compat

### Pump: eager per-log processing

- Removed `pending_logs` buffer, `process_completed_block`, `handle_block_header` (old variant), `handle_timeout` (old variant), `backfill_single_block`
- `WsEvent::Log(log)` → `apply_log` → `solve_dirty` immediately
- Block boundary detected by `log.block_number > current_block` (primary) or `header.number > current_block` (empty-block fallback)
- Block headers provide metadata, handle empty blocks, gap backfill

## Acceptance Criteria

- [x] Sub-engine `apply_*` methods return affected pool keys
- [x] `UniswapEngine::apply_log` + `solve_dirty` work correctly
- [x] Existing `process_block` still works (backward compat)
- [x] Pump processes logs immediately, no pending_logs buffer

- [x] Bot runs successfully end-to-end with eager processing
