## Problem

The Rust pump buffers all WS logs in `pending_logs` until a `newHeads` header arrives, creating a 1-block (~12s) latency before events are visible to the solver. This makes the arbitrage bot uncompetitive.

## Design

### Sub-engines: return affected pool keys from individual `apply_*` methods

- `V2BlockEngine::apply_sync` → `Option<u64>` (forward pool key)
- `V3BlockEngine::apply_swap` → `Option<u64>`
- `V3BlockEngine::apply_liquidity_update` → `Option<u64>`
- `V4BlockEngine::apply_swap` → `Option<(u64, u64)>` (fwd+rev keys)
- `V4BlockEngine::apply_liquidity_update` → `Option<(u64, u64)>`

### Top-level UniswapEngine: split process_block into apply_log + finalize_block

- `apply_log(log, block_number)` — decode, route to sub-engine, accumulate dirty pool keys
- `finalize_block(block_number, metadata)` — expire buffered events, rebuild_and_solve_affected with dirty keys, compute_diff_and_send, clear dirty sets
- Keep `process_block` as `apply_log × N + finalize_block` for backward compat

### Pump: immediate log processing

- Remove `pending_logs` buffer
- `WsEvent::Log(log)` → `engine.apply_log(log, block_number)`, add to dirty sets
- Block boundary detected by `log.block_number > current_block` (primary) or `header.number > current_block` (empty-block fallback)
- On boundary: `engine.finalize_block(previous_block, metadata)`, clear dirty sets, advance

### Timeline (new)

```
Block N log arrives → apply_log → state updated immediately
  (if log.block_number > current_block → finalize previous block)
Block N header arrives → record metadata (timestamp, fees)
  (if header.number > current_block → finalize previous block if not already done)
```

No 1-block delay. Block boundary triggers solve+dispatch as soon as the first log of the next block arrives (or the header, for empty blocks).

## Acceptance Criteria

- [ ] Sub-engine `apply_*` methods return affected pool keys
- [ ] `UniswapEngine::apply_log` + `finalize_block` work correctly
- [ ] Existing `process_block` still works (backward compat)
- [ ] Pump processes logs immediately, no pending_logs buffer
- [ ] Rust tests pass
- [ ] Bot runs successfully end-to-end with eager processing
