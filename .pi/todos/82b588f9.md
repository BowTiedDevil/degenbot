## Design
A second tstore-based executor using a compact command-bytecode VM pattern instead of the generic payload queue. Off-chain code pre-computes the entire execution plan and encodes it as a flat command stream. The contract is a pure VM — decode and execute commands without on-chain decision-making.

## Command Set
| Byte | Command | Layout |
|------|---------|--------|
| 0x00 | V2_SWAP | [0x00][pool_idx:1][zfo:1][amount_out:32][recipient_idx:1][forward_len:2][forward_data:N][0xFF] |
| 0x01 | V3_SWAP | [0x01][pool_idx:1][zfo:1][amount_specified:32][sqrt_limit:20][recipient_idx:1][forward_len:2][forward_data:N][0xFF] |
| 0x02 | V4_SWAP | [0x02][c0_idx:1][c1_idx:1][fee:3][ts:3][hooks_idx:1][zfo:1][amount_specified:32][sqrt_limit:20][0xFF] |
| 0x03 | V4_TAKE | [0x03][currency_idx:1][recipient_idx:1][amount:32][0xFF] |
| 0x04 | V4_SYNC | [0x04][currency_idx:1][0xFF] |
| 0x05 | V4_SETTLE | [0x05][0xFF] |
| 0x06 | V4_SETTLE_NATIVE | [0x06][amount:32][0xFF] |
| 0x07 | ERC20_TRANSFER | [0x07][token_idx:1][recipient_idx:1][amount:32][0xFF] |
| 0x08 | WETH_DEPOSIT | [0x08][amount:32][0xFF] |
| 0x09 | WETH_WITHDRAW | [0x09][amount:32][0xFF] |
| 0x0A | V4_UNLOCK | [0x0A][pm_idx:1][forward_len:2][forward_data:N][0xFF] |
| 0xFF | SEPARATOR | Command terminator |

## Key Differences from tstore_executor
- No payload queue — command stream IS the continuation mechanism
- No delta ledger — all amounts pre-computed off-chain
- No auto-pay — explicit ERC-20 transfers in command stream
- No Phase 0/1/2/3 — commands execute in encoded order
- No will_callback flag — auto-registered on swap commands
- Callbacks forward command stream through data parameter (full bytes passthrough)
- V2/V3/V4 callback handlers are identical: just _process_commands(data)
