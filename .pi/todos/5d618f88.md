## Status
The contract improvements (4-phase unlockCallback, t_v4_deltas full-currency ledger, dynamic_amount, Phase 0 pre-settle) have resolved the major V4 settlement issues. The remaining task for this TODO was the unlockCallback ordering — payloads vs V4 swaps.

The current contract ordering is:
- Phase 0: Pre-settle (before V4 swaps)
- Phase 1: V4 swaps
- Phase 2: Queued payloads
- Phase 3: Auto-settle

This is the CORRECT ordering for V4→V3 and V4→V2 (take forward from V4, then give to V3/V2). For V3→V4 and V2→V4, the forward token is synced and transferred before unlock, then Phase 0 settles it.

## Resolution: RESOLVED by contract improvements. The old issue about "swap Phase 1 before payloads Phase 2" was the wrong framing — the contract's Phase 0 + Phase 1 + Phase 2 + Phase 3 ordering handles all path types correctly, as verified by the 10 passing contract tests.
