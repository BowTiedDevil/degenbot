**Master: `TODO-215e9e66` (ADR-006).** Deps: slices 4 + 5. Addresses ADR-006 (Idea 1, coalesced drain trigger).

**Status: COMPLETE (committed).**

**Goal.** The drain-point solve tick. `SolveCoordinator` subscribes to `BlockPump`'s drain (empty log queue) + block-boundary events and asks each attached engine to solve its dirties per the **coalesced α policy** (the existing eager-processing invariant restated in bus vocabulary — no new solve debounce; today's existing 50ms send-result debounce stays unchanged). The engine takes its `Mutex` + a core `read()` guard to re-derive `IntHopState`/`IntV3TickRangeSequence` from current `BotState` and re-solve affected paths (lock order engine-then-core preserved).

**What landed (ADR-006 slice 6):**
- New `pub(crate) trait Engine` (`rust/src/bot_core/engine.rs`) — the Bot→Engine drain-side trait seam (6 methods, all `&self`): `solve_dirty`, `send_result_batch`, `has_dirty_paths`, `finalize_block`, `handle_reorg`, `last_processed_block`. ADR-006 D4 "Engine-as-EventSink topology" realized: `SolveCoordinator` holds `Arc<dyn Engine>` and never names `Mutex`/`UniswapEngine`. A future `AaveLiquidationEngine` impls the same trait with zero Bot/pump/coordinator change — the strategy-extension seam.
- `EngineHandle` (`rust/src/optimizers/uniswap_engine/engine_handle.rs`) — owning `Arc<dyn Engine>` wrapper around the shared `Arc<parking_lot::Mutex<UniswapEngine>>`; impls `Engine` by lock-then-forward. Replaces slice-5a `EngineDrainSink` (deleted).
- `SolveCoordinator` (`rust/src/bot_core/solve_coordinator.rs`) — holds `Vec<Arc<dyn Engine>>` (multi-engine-honest shape; one engine today). `impl DrainSink` fans `on_drain`/`on_send`/`finalize_block`/`on_reorg` to every engine under a coarse `drain_lock`. `last_processed_block()` takes `drain_lock` and returns `last_drained_block` — **blocks Python polls until any in-flight drain completes**, returning a drain-consistent "good" block (no Rust/Python race over a mid-drain cursor read). Lock order `drain_lock` → engine-Mutex → `BotState` RwLock, never reversed.
- Precondition 1 (all engines registered before start) + precondition 2 (cursors agree at start) — **documented + asserted** via `SolveCoordinator::start()` (panics on cursor divergence — a wiring bug). `py_binding.rs` calls `coordinator.start()` in both `start()` and `resume()` paths before the pump's WS phase begins. The *divergence machinery* (per-engine backfill queues, scoped dispatch, mid-flight engine join) is **not built** — explicitly deferred; the seam (`Vec<Engine>`) is multi-engine-honest without the machinery.
- `SolvePolicy` enum (`Drain`/`Eager`/`Block`/`Manual`) **DEFERRED** — `on_drain` hardcoded to Drain with a `// DEFERRED` comment at the dispatch point. One consumer short of the seam bar; recorded in ADR-006.
- Send-result path: pump's `DEBOUNCE_MS=50` send-debounce **unchanged**; `on_send` fans to `engine.send_result_batch` (the existing `tokio::mpsc` `ResultBatch` channel → Python).
- Python-facing `last_processed_block` routed through `coordinator.last_processed_block()` (was `engine.lock().last_processed_block()`) so polls get the drain-consistent block.
- `EngineDrainSink` deleted (slice-5a placeholder superseded).
