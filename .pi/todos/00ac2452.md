## Problem

V3 snapshot loading and backfill was not working — the V3 tracker's `snapshot` property was always `None`, causing backfill to be skipped. This meant V3 pools in the Rust engine were registered with whatever sparse tick data the builder got from on-chain probing, without the benefit of DB-stored snapshots or event backfill.

## Fix Applied

Added V3 snapshot creation from DB and passed it to `add_tracker()`, mirroring the pattern used in `base_backrun_v4_v3_testing.py`:

1. **`examples/eth_backrun_v2_v3_v4_rust.py`**: 
   - Added imports for `V3DatabaseSnapshot` and `UniswapV3LiquiditySnapshot`
   - Created `v3_snapshot` from DB before tracker creation (with `try/except ValueError` fallback)
   - Passed `snapshot=v3_snapshot` to all three V3 `add_tracker()` calls (Uniswap, Sushi, Pancake)

2. **`examples/v4_v3_focused.py`**:
   - Same pattern: create snapshot from DB, pass to `add_tracker()`
   - Also fixed `process_block` calls (was calling `engine.process_block` instead of `engine_registry.process_block`)
