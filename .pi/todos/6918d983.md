## Summary
V3_SWAP_DELTA (0x31) and ERC20_XFER_BALANCE (0x11) are compact commands that eliminate amount encoding by reading from on-chain state. V3_SWAP_DELTA reads the V3 swap's input amount from PM exttload (4 bytes vs 17 bytes for V3_SWAP_COMPACT). ERC20_XFER_BALANCE transfers the executor's entire balance of a token (3 bytes vs 35 bytes for ERC20_TRANSFER with a 32-byte amount).

## V3_SWAP_DELTA (0x31)

### When to Use
Inside a V4 unlock context where a prior V4 swap has created a positive PM delta for the V3 pool's input currency. The V3 swap reads its input amount from the PM delta instead of encoding it in calldata.

**Caveat**: V3 auto-pay (empty forward_data) requires the executor to PHYSICALLY hold the input ERC-20 tokens at callback time. If the tokens come from the PM (V4→V3 path), the standard approach is V4_TAKE (which transfers physical tokens) + V3_SWAP_COMPACT with auto-pay. V3_SWAP_DELTA skips the V4_TAKE, but the executor won't have physical tokens for auto-pay.

**Best use**: V3→V4 paths where V3's output goes to PM (recipient=PM). V3 sends output to PM, PM has a positive delta, and V4 settlement handles it. But we need to verify the IIA constraints carefully.

### Where It Saves
- 4 bytes vs 17 bytes for V3_SWAP_COMPACT (saves 13 bytes per V3 swap)
- Useful in V4→V3→V4 3-hop paths where V3 is inside V4 unlock

## ERC20_XFER_BALANCE (0x11)

### When to Use
When you need to transfer the executor's ENTIRE balance of a token. Common cases:
- V3→V2 paths: transfer all remaining WETH to V2 for repayment
- V2→V2 paths: sweep residual tokens
- Any path where the full balance should be moved to the next hop

### Encoding
```python
def enc_erc20_xfer_balance(token_idx: int, recipient_idx: int) -> bytes:
    """ERC20_XFER_BALANCE: [0x11][token_idx:1][recipient_idx:1] — 3 bytes."""
```

### Where It Saves
- 3 bytes vs 35 bytes for ERC20_TRANSFER (saves 32 bytes per transfer)
- Pure calldata win: `balanceOf` read is ~200 gas (warm), but saves 512–2048 gas in calldata cost

### Integration Points
- V3→V2 2-hop: replace `enc_erc20_transfer(weth_idx, v2_idx, optimal_input)` with `enc_erc20_xfer_balance(weth_idx, v2_idx)` 
- V2→V2 N-hop: replace the final WETH repayment transfer
- V4 settlement: use instead of explicit amount transfers when sweeping
