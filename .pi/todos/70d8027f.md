Performance and consistency fix in `rust/src/optimizers/v3_block_engine.rs` and `rust/src/optimizers/v4_block_engine.rs`.

`V3PoolState` currently holds `std::sync::Mutex<TickRangeCache>` and `get_cached_tick_ranges` clones the whole `Vec<V3TickRangeForSolver>` on every access. This violates the project-wide `parking_lot::Mutex` discipline and repeatedly copies ranges containing `U256` sqrt prices when multiple paths reference the same pool/direction.

Tasks:
- Replace `std::sync::Mutex<TickRangeCache>` with `parking_lot::Mutex<TickRangeCache>`.
- Store cached ranges as `Arc<[V3TickRangeForSolver]>` (or `Arc<Vec<...>>`) inside the cache.
- Return a cheap `Arc::clone` from `get_cached_tick_ranges`.
- Update `build_sequence`, `build_int_v3_hop`, `build_int_v3_sequence` (and V4 equivalents) to slice the shared buffer instead of cloning/truncating a fresh `Vec`.
- Verify no panic paths rely on `std::sync::Mutex` poisoning semantics.
- Run `just test-rust` and `just lint-rust`.
