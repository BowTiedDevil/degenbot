## Problem

`compute_diff_and_send` builds `new_above` (HashMap), `new_above_ids` (HashSet), and `delivered_ids` (HashSet) from `self.results` every time. With small result sets (typically 0-20 above-threshold paths), this is cheap but could be avoided.

Location: `rust/src/optimizers/uniswap_engine.rs` → `compute_diff_and_send` (~line 1003)

## Fix

Compute diff directly from sorted vecs (both `results` and `delivered` are keyed by path_id). A linear scan replaces HashMap construction and the `PartialEq` comparison on `SolvePathResult` fields. Alternatively, iterate `delivered` keys to find expired (in delivered but not in results), and iterate results to find fresh/updated.

Even simpler: since the delivered set is typically small, just iterate both vecs in order (they're sorted by path_id) like a merge-sort diff — O(N+M) with zero allocation beyond the output vecs.

## Current Code Pattern

```rust
let new_above: HashMap<u64, SolvePathResult> = self.results.iter()
    .filter(|(_, r)| r.profit > self.min_profit && r.profit < self.max_profit)
    .map(|(id, r)| (*id, r.clone()))  // ← clone + HashMap alloc
    .collect();
let new_above_ids: HashSet<u64> = new_above.keys().copied().collect();  // ← another alloc
let delivered_ids: HashSet<u64> = self.delivered.keys().copied().collect();  // ← another alloc
```
