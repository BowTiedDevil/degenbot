Replace the current pump pattern (build HashSet once at startup → filter logs against frozen set) with a per-block snapshot approach:

1. At the start of each block processing cycle, briefly acquire the engine lock and snapshot the address HashMaps (just reading the keys — O(pools), trivially fast). The HashMaps are the source of truth — no separate address set needed.
2. Release the lock
3. Filter the buffered logs against the snapshot (O(n) where n = log count, no lock held)
4. Reacquire the lock for `process_block`

**Rationale**: Filtering is O(n) against all Ethereum logs — potentially thousands of irrelevant events per block. Holding the lock through that blocks Python registration. The snapshot approach keeps the lock hold to O(pools). The gap between snapshot and reacquire is harmless: Swap/Sync for newly-registered pools are already reflected in registration state; Mint/Burn are caught by the sub-engine event buffer.

**Decisions**:
- Address filter is a per-block snapshot, not a frozen set
- Filter against HashMap key membership directly (no separate HashSet)
- Lock released during filtering to avoid blocking Python registration
- Snapshot-then-filter-then-reacquire pattern
