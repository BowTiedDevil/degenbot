## Summary
V4_BATCH (0x42) packs multiple V4 swaps into a single command with a tight loop and auto-settles at the end. It eliminates per-command dispatch overhead and replaces separate V4_TAKE/V4_SETTLE commands with a single auto-settle. For V4→V4 paths, V4_BATCH is the most calldata-efficient encoding.

## Current vs V4_BATCH

### 2-hop V4→V4 (same currency)
```python
# Current: two separate V4_SWAP commands
inner = enc_v4_swap_compact(...)  # 21 bytes
inner += enc_v4_swap_dynamic(...)  # 9 bytes
inner += enc_v4_take_delta(...)    # 3 bytes
inner += enc_v4_settle_all()       # 1 byte
# Total inner: 34 bytes

# With V4_BATCH:
inner = enc_v4_batch([
    (c0_a, c1_a, fee_a, ts_a, hooks, zfo_a, amount_a),  # 20 bytes
    (c0_b, c1_b, fee_b, ts_b, hooks, zfo_b, 0),         # 20 bytes (dynamic, amount=0)
])
# Total inner: 2 + 2*20 = 42 bytes, but saves on settlement overhead
# Net calldata: similar, but V4_BATCH has auto-settle built in
```

### Benefit Analysis
Per the BENCHMARKS.md:
- Same-currency V4→V4: explicit 192 bytes vs V4_BATCH 157 bytes (−35 bytes)
- Cross-currency V4→V4: explicit 230 bytes vs V4_BATCH 142 bytes (−88 bytes!)
- V4_BATCH is −16.9% vs tstore on same-currency, −28.7% on cross-currency

### Implementation in eth_backrun_helpers.py

**_encode_cmd_v4_v4()**: For same-currency paths, use V4_BATCH:
```python
inner = enc_v4_batch([
    (c0_a_idx, c1_a_idx, hop_a.fee, hop_a.tick_spacing, no_hooks, hop_a.zfo, optimal_input),
    (c0_b_idx, c1_b_idx, hop_b.fee, hop_b.tick_spacing, no_hooks, hop_b.zfo, 0),  # dynamic
])
```
Note: V4_BATCH auto-settles, so V4_SETTLE_ALL is included internally.

**_3hop_v4_v4_v4()**: Use V4_BATCH with 3 entries:
```python
inner = enc_v4_batch([
    (..., amount=optimal_input),
    (..., amount=0),  # dynamic
    (..., amount=0),  # dynamic
])
inner += enc_v4_mint_compact(weth_idx, executor_idx, profit)  # profit not included in batch
```

### Important Constraints
- MAX_V4_BATCH_SWAPS = 8 (contract limit)
- After all swaps, auto-settles native ETH and WETH deltas (not intermediate ERC-20s)
- For cross-currency V4→V4 paths, intermediate ERC-20 deltas cancel in the batch
- Dynamic amounts (amount=0) read from: first dynamic = PM exttload, subsequent = previous swap's BalanceDelta
- Cannot use V4_BATCH if intermediate settlements are needed between swaps
