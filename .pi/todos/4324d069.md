**Slice 11 of the Polars three-layer migration (ADR-005; ADR-003 "third family").** Master: `TODO-7e24d695`. Deps: slice 10 (engine unified, so Curve pools can be engine-managed too). Large — expect sub-slicing (pure-math port → state port → provider port → companion).

**Goal.** Extend `PoolEntry` with a Curve variant + Curve Rust state struct + port `CurveDataProvider` to Rust + make `CurveStableswapPool` a companion over `PyLiquidityPool`. `DyCalculator` strategies migrate to Rust one variant at a time (B-ii). Curve is currently the MOST Polars-like Python pool (`CurveDataProvider` 13-method seam + `DyCalculator` strategy seam, already I/O-free) — this slice lifts it into the Rust core.

**Rust (new).**
- Curve state struct (reserves / D / virtual_price / price_scale / gamma / etc. — the `BoundedCache`/`PerBlockCache` data). NOT `StateCache` — Curve uses dict-based per-block cache; mirror in Rust.
- `PoolEntry::Curve(CurvePoolState)` — adds a third family, which triggers the ADR-003 question: keep the inline-`PoolEntry` + `Bot::apply_*` pattern or extract the `LiquidityMap` generic. **Decision point** during this slice (ADR-003 deferred this until a third family ports — now's the moment).
- `Bot::register_curve_pool` + `get_dy` delegating to Rust calculators.
- `CurveDataProvider`-in-Rust (the 13 methods: `D`/`gamma`/`virtual_price`/`base_virtual_price`/`price_scale`/`admin_balances`/`lending_rates`/`redemption_price`/`block_timestamp`/`block_number`/`token_balance`/`token_total_supply`/`is_crypto`).
- `PyBot.register_curve_pool` + Curve read getters on `PyLiquidityPool`.

**Python.** `CurveStableswapPool` (`src/degenbot/curve/curve_stableswap_liquidity_pool.py`, 1140 lines) wraps `PyLiquidityPool`; `get_dy`/`get_dx` delegate; `CurveDataProvider` becomes a Python→Rust adapter OR the Rust provider is wired by the builder (`CurveDataProviderImpl` with `ProviderAdapter`). `DyCalculator` strategies (`make_swap_style_calculator`/`make_metapool_calculator`/`make_metapool_underlying_calculator`) stay Python initially (B-ii), then migrate variant-by-variant. Pure math already in `calculations/stableswap.py` (`stableswap_get_y`/`stableswap_newton_y`) — these are the Rust-port source of truth.

**Builders.** `CurvePoolBuilder` constructs via `PyBot.register_curve_pool`, wraps.

**Tests.** Curve stableswap calc tests (cross-check against `contract_reference/`); lending/crypto pool variant tests; `DyCalculationInputs` round-trip.

**Consistency at boundary.** Curve calc byte-identical (ports against `contract_reference` + Python oracle). Third `PoolEntry` variant added cleanly. All Curve tests pass.

**Acceptance.** `cargo`/`ruff`/`ty` green; Curve tests pass; `PoolEntry::Curve` round-trips; `DexIdentity`-equivalent Curve identity (factory/coins/n/virtual_price variants) Rust-side per the standalone-constraint.
