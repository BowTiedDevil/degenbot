**Master: `TODO-215e9e66` (ADR-006).** Deps: slices 1-7. Addresses ADR-006 D5 (one Bot per chain; `bot.py` unwinds its swallowed multi-chain managers).

**Goal.** `bot.py` (608 lines today) becomes a single-chain facade over one `PyBot`. The multi-chain `ConnectionManager`/per-`TokenEntry.chain_id`/`PoolRegistry`/`TokenRegistry` plumbing that `Bot` *swallowed* (the "multi-chain by accident" — confirmed in grilling) moves to the caller: a Python user wanting two chains instantiates two `Bot`s, with no coordination layer between them.

**Python work.**
- `src/degenbot/bot.py`: `Bot.__init__` takes a single `chain_id` (no `connections` multi-chain manager); construct `self._py_bot = PyBot()` with `chain_id`; remove the multi-chain `connections.get_provider(chain_id)` indirection → one provider per Bot (matches D4's "Bot owns RPC"). The swallowed `ConnectionManager`, `PoolRegistry`/`TokenRegistry`/`ManagedPoolRegistry` either move to caller-side helpers or slim to single-chain-only structs (drop the `chain_id` keys).
- `Bot.from_config_file()`: keep as the constructor entry, but it now builds a ONE-chain `Bot` (read the configured default chain's RPC + chain_id); a user with multiple chains calls `Bot.from_config_file(chain_id=...)` or `Bot(chain_id=..., rpc_url=...)` twice.
- The builders (`Erc20Builder`, `V2/V3/V4PoolBuilder`) + `BuilderContext`: keep taking `py_bot`; remove the (`chain_id`-keyed) cross-chain registry lookups — one chain, one builder context.
- `get_provider`, `start_listening`, `get_token_balance`/`approval`/`total_supply`, `get_ether_balance`: collapse from `chain_id`-dispatched to single-chain methods. The WS subscription / I/O that today lives on `Bot` (and overlaps with `BlockPump` owning WS transport post-slice-5) reconciles: `Bot.start()` delegates to the Rust `BlockPump`; `start_listening` either retires or becomes a thin shim.
- `AsyncBot` (`src/degenbot/async_bot.py`): mirror the single-chain simplification.

**Tests.**
- Construct two `Bot`s (mainnet + polygon) in one test process; assert they're fully independent (separate `PyBot`s, separate Rust `Bot`s, no shared registry, no cross-talk). This is D5's positive proof.
- Existing single-chain bot tests updated to the new constructor shape.

**Note.** The migration is **breaking** (per AGENTS.md "design standalone features without a backwards compatibility layer"). Public-API breakage accepted (0.x major refactor). Update CHANGELOG (per the update-changelog skill) and migration notes if any.

**Acceptance.** `just test-python` green; `bot.py` is single-chain (one `chain_id` ctor arg, one provider); the swallowed multi-chain managers retired/moved; two-chain independence proven. `AsyncBot` mirrors. The library `Bot` now matches the standalone-Rust `Bot::new(chain_id, rpc_url)` construction shape — the Polars split-UX promise for D5.
