## Outcome: Done — implemented as Option B (engine method) for testability

The todo's original sketch (Option A: thread a param into the pump's `finalize_if_dirty`) couldn't satisfy AGENTS.md's Red/Green TDD requirement because `UniswapEnginePump` can't be constructed without a live WS connection (`subscribe()`). So I extracted the finalize logic onto `UniswapEngine` (where its siblings `solve_dirty`/`send_result_batch`/`process_block_and_send` already live and where tests construct the engine directly), and made the pump a thin delegating wrapper. This still satisfies the acceptance criterion (signature takes `&BlockMetadata`; both call sites pass `&current_metadata`) AND gives the new metadata-threading contract a proper unit test.

## Changes

### New engine method — `rust/src/optimizers/uniswap_engine/event_routing.rs`
`UniswapEngine::finalize_block(&mut self, block, metadata, last_solved_block: &mut u64, has_logs_this_block: &mut bool)`: guard `if block > *last_solved_block` → if `has_dirty_paths()` solve+send with `metadata`; else if `*has_logs_this_block` `process_block_and_send(&[], block, metadata)`; advance `last_solved_block`; clear `has_logs_this_block`. Doc comment explains the guard semantics + the metadata-threading rationale (references the `ResultBatch` CONTEXT note).

### Pump — `rust/src/optimizers/uniswap_engine_pump.rs`
- `finalize_if_dirty` now takes `metadata: &BlockMetadata` and delegates: `self.engine.lock().finalize_block(block, metadata, last_solved_block, has_logs_this_block)`. Replaced the long TODO-096065c9 "empty metadata / latent sharp edge" doc comment (no longer accurate) with a short pointer to `finalize_block`.
- Both call sites in `run_with_stream` (log-arm ~:608, header-arm ~:659) now pass `&current_metadata`.

### Test (Red→Green TDD) — `rust/src/optimizers/uniswap_engine/tests.rs`
Added `finalize_block_threads_metadata_into_send`: constructs an engine + result channel, registers a profitable pure-V2 path via `register_and_solve_path`, marks a pool dirty, sets `last_solved_block=0 < block=10`, calls `finalize_block` with non-default `BlockMetadata`, asserts the emitted `ResultBatch` carries the passed metadata (`timestamp`/`base_fee_per_gas`/`gas_used`/`gas_limit`) + the profitable path is in `fresh`/`updated` + `last_solved_block` advanced + logs flag cleared.
- **Red**: test referenced nonexistent `finalize_block` → compile error `E0599: no method named finalize_block` (confirmed).
- **Green**: implemented `finalize_block` + threaded metadata → test passes.

### Docs — `rust/CONTEXT.md`
Updated the `ResultBatch` metadata note (line ~150) for the post-fix state: the hot-loop finalize path now threads real `current_metadata`; only `backfill_range` (solves, doesn't send) and the vestigial `solve_all_paths` (no callers) still use `BlockMetadata::default()`; neither can carry a profitable result.
