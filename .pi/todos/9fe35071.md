## Resolution

V4-V4 `CurrencyNotSettled` root cause: **`V4_SETTLE` (0x55) is a raw `PM.settle()` call, NOT an auto-settle.** It only credits tokens after sync+transfer. It does NOT read PM deltas or settle outstanding debts.

In the same-currency V4-V4 path (V4_SWAP_DYNAMIC), V4 swap math produces rounding residuals (1-2 wei) on both the intermediate ERC-20 and the input/output currency. With `V4_TAKE(explicit_amount)` + `V4_SETTLE()`, these residuals are never settled → `CurrencyNotSettled`.

### Fix
Replaced `V4_TAKE` + `V4_SETTLE` with `V4_TAKE_DELTA` + `V4_SETTLE_ALL`:
- **`V4_TAKE_DELTA`** reads the actual PM delta (not the solver's prediction) and takes it. Handles exact profit amount regardless of rounding.
- **`V4_SETTLE_ALL`** iterates all nonzero PM deltas and settles them via `_v4_settle_currency()`. Handles 1-2 wei rounding residuals on the intermediate ERC-20.

Applied same fix to the currency_gap path (WETH↔ETH conversion) which also had `V4_SETTLE` → `V4_SETTLE_ALL`.

### Results
- Before: 30 V4-V4 sim-ok, ~4,304 CurrencyNotSettled
- After: 66 V4-V4 sim-ok, 0 CurrencyNotSettled, 44 phantom-profit rejections (V4_TAKE_DELTA: non-positive delta)

### Remaining V4-V4 failures
- ~80 `V4_TAKE_DELTA: non-positive delta`: Phantom-profit paths where solver predicted profit but on-chain simulation shows actual V4 delta is ≤0. These are correct rejections.
- ~37 empty reverts: Gas exceeds profit or similar. Not encoding bugs.
