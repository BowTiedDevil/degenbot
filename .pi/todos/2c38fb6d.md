Ergonomics and correctness cleanup in `rust/src/optimizers/uniswap_engine/event_routing.rs` and the sub-engines.

`apply_log` today handles dual-orientation keys inconsistently:
- V2: `apply_sync` returns only a forward key; the caller inserts both `fwd_key` and `fwd_key + 1`.
- V4: `apply_swap` returns both forward and reverse keys.
- V3: only one key is returned and inserted.

This leaks the engine-internal key allocation scheme across the routing layer and risks missing a reverse orientation if the convention changes.

Tasks:
- Introduce a small `AffectedKeys` (or `DirtyKeys`) return type that each sub-engine populates with every orientation/key it manages.
- Update `apply_sync` (V2), `apply_swap` (V3/V4), and `apply_liquidity_update` to return this abstraction.
- Replace manual `+ 1` insertion in `event_routing.rs` with iteration over `affected.keys()`.
- Run `just test-rust` and `just lint-rust`.
