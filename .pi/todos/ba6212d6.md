**Master: `TODO-215e9e66` (ADR-006).** Addresses ADR-006 D1+D2. **Supersedes `TODO-408eb2c1`** (ADR-005 Slice 10: lock unification) — that slice's scope ("just unify the Arc") is folded into this broader one; close `TODO-408eb2c1` as superseded.

**Goal.** Collapse the two `Bot` instances into one shared `Arc<RwLock<Bot>>`; give `PyBot` and `UniswapEngine` adopt-a-core constructors; flip the engine's core lock `Mutex`→`RwLock` and classify every core access read vs write. The §17 stale-state caveat's root cause (pump mutates Bot B; `PyLiquidityPool` reads Bot A) is dissolved by the shared Arc.

**Rust work.**
- `rust/src/bot_core/py_bot.rs`: today `core: Arc<RwLock<Bot>>` is constructed in `new()` (line 53). Add `PyBot::from_core(core: Arc<RwLock<Bot>>)` adopting an existing Arc; add a way for the engine to obtain the Arc (a `pub(crate) fn core_arc(&self) -> Arc<RwLock<Bot>>` or hand-off at engine construction).
- `rust/src/bot_core/mod.rs`: `Bot` gains a `chain_id: u64` field (D1 + D4 precondition — `Bot::new(chain_id)` signature; the per-`TokenEntry.chain_id` becomes a redundant mirror or is dropped). Keep `Bot::new()` as standalone sugar for no-pyo3 tests (becomes `with_core(Arc::new(...))`).
- `rust/src/optimizers/uniswap_engine/mod.rs`: `core: Arc<parking_lot::Mutex<Bot>>` (line 338, `new()` at 401 allocating its own) → `core: Arc<parking_lot::RwLock<Bot>>`. Add `UniswapEngine::with_core(core: Arc<RwLock<Bot>>)`; `new()` → `with_core(Arc::new(RwLock::new(Bot::new(...))))`.
- **D2 classification pass (~30 sites):** every `self.core.lock()` in `event_routing.rs`/`lifecycle.rs`/`solver_dispatch.rs`/`diagnostic.rs`/`mod.rs` → `self.core.read()` or `self.core.write()`:
  - **write:** `apply_v2_sync`/`apply_v3_swap`/`apply_v3_liquidity_update`/`apply_v4_swap`/`apply_v4_liquidity_update`, `buffer_backfill_v3/v4_liquidity_update`, `expire_v3/v4_buffered`, `flush_v3/v4_buffer`, `set_v3/v4_buffer_max_age`, `register_v2/v3/v4_pool` (pre-D3, still here for now), `restore_*`.
  - **read:** `get_v2_pool_state`/`get_v3_pool`/`get_v4_pool`, `v2/v3/v4_pool_count`, `v4_registered_pool_managers`, `resolve_path`/solve reads, `diagnostic` reads.
- `rust/src/optimizers/uniswap_engine/py_binding.rs`: `PyUniswapArbEngine::new()` constructs the engine via `with_core` over `PyBot`'s Arc (not its own `Bot::new()`). Accept an optional `py_bot` arg so the Python `UniswapArbEngine(py_bot=...)` path adopts the shared core.

**Lock-ordering invariant (preserve ADR-006 D2):** engine-then-core unchanged; `PyBot`/`PyLiquidityPool` methods take core `RwLock` alone. Pump's `engine.lock()` call sites (~10 in `uniswap_engine_pump.rs`) are untouched. Concurrency note: the pump's core-**write** now contends with Python `PyLiquidityPool` core-**read** on the same RwLock — the intended tradeoff (closes the stale-state caveat); document this.
