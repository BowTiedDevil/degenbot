## Fixed
Rewrote V3-V3 encoder to use reverse-order direct custody:
- Start with V3_B (the "last" pool in the path direction)
- V3_A sends output directly to V3_B (not executor) — satisfies IIA
- V3_A auto-pay uses WETH from V3_B's output — no pre-existing balance needed
- Also fixed V2-V3: moved ERC20_TRANSFER into V3's forward_data (not before V3.swap())

## Key insight from optimized tests
Reverse-order V3 direct custody: each nested swap sends output directly to the
outer pool's address (recipient=pool_idx, not executor). Tokens arrive DURING
the outer pool's callback, satisfying IIA. No executor balance required.
