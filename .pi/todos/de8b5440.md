## Problem

Every `solve_dirty` call rebuilds `self.results` by cloning *every* unchanged result. With ~4000 paths and ~10 dirty pools triggering ~100-200 affected paths, that's 3800 clones of `SolvePathResult` (containing `Vec<U256>` fields) per solve. At 1-3 solves per block, that's 10K+ clone operations per block for unchanged data.

Location: `rust/src/optimizers/uniswap_engine.rs` → `rebuild_and_solve_affected` (~line 604)

## Fix

Use an in-place update pattern — remove affected results from `self.results`, solve, then extend. Or maintain a `HashMap<u64, SolvePathResult>` instead of `Vec<(u64, SolvePathResult)>` so updates don't require rebuild/sort.

## Current Code Pattern

```rust
// Carry forward unchanged results
for (path_id, solve_result) in &self.results {
    if !affected_path_ids.contains(path_id) {
        new_results.push((*path_id, solve_result.clone()));  // ← clones every unchanged result
    }
}
// Solve affected paths
for &path_id in &affected_path_ids { ... }
new_results.sort_unstable_by_key(|(path_id, _)| *path_id);
self.results = new_results;
```
