## Problem

Each `(HopType, pool_key)` maps to a `HashSet<u64>` of path IDs. For 2-hop paths, each pool is in exactly 1-2 paths. `HashSet` has ~48 bytes overhead per entry + hash computation. With thousands of pools in `pool_to_paths`, this adds memory and lookup overhead.

Location: `rust/src/optimizers/uniswap_engine.rs` → `pool_to_paths` field (~line 193)

## Fix

Replace `HashSet<u64>` with `SmallVec<[u64; 4]>` in `pool_to_paths`. For the common case (1-3 paths per pool), this avoids heap allocation entirely. Dedup lazily when collecting `affected_path_ids` (or use a `HashSet<u64>` only at the collection step).

Alternative: since path IDs are unique within a pool's set, a sorted `Vec<u64>` with binary search would also work and be more cache-friendly.

## Current Code Pattern

```rust
pool_to_paths: HashMap<(HopType, u64), HashSet<u64>>,
```
