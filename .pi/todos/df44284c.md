## Summary
Apply the direct custody patterns from the executor user guide (§10-12) to the path encoders. The current encoders make suboptimal choices for some path types — using callbacks where V2_SWAP_DIRECT/V2_SWAP_CALC would be more efficient, and missing opportunities for direct delivery to V2/V3 pools.

## Key Direct Custody Patterns (from user guide §10)

### Already Correct
- V4→V2: V4_TAKE→V2 pair (excess balance) → already uses this pattern ✅
- V3→V3: Reverse-order direct custody → already correct ✅
- V4→V4: Delta netting → already correct ✅

### Needs Review

#### 1. V2→V3 (2-hop): User guide uses V3-reverse with V2 inside V3 callback
Current code: V2 flash borrow → V3 in callback (forward-order)
User guide (§11.2): V3 outermost, V2 inside V3 callback with V2_SWAP_DIRECT to V3b (IIA ✓)

The current implementation works but may use more transfers than necessary. The user guide pattern has 3 transfers vs 4 for naive approach.

#### 2. V3→V2 (2-hop): Direct custody recipient
Current: V3 sends USDC to executor, then explicit USDC→V2 transfer
User guide (§11.4): V3 sends output DIRECTLY to V2b (recipient=V2b), then V2c via V2_SWAP_DIRECT

The current code already has `enc_v2_swap_compact` for V2 in most V3→V2 paths, but could use V2_SWAP_DIRECT more aggressively when excess balance is at V2.

#### 3. V2→V4 (2-hop): V2 callback sends forward_b to PM
Current: V2 callback → V4 unlock → take output
User guide (§11.3): Inside V4 unlock, V2a sends USDC directly to PM (V2_SWAP_CALC with recipient=PM), eliminating the executor→PM transfer

#### 4. V4→V3 (2-hop): V4_TAKE inside V3 callback (IIA ✓)
Current: All inside V4_UNLOCK, V4_TAKE to executor, V3 auto-pay
User guide (§11.8): V3 runs inside V4 unlock, V4_TAKE sends USDC directly to V3 during V3's callback (between balance_before/after snapshots)

This is a different routing for V4→V3 that satisfies IIA more directly. Current approach (take→executor→V3 auto-pay) works but the V4_TAKE→V3c-during-callback pattern eliminates the need for executor to hold tokens.

## Implementation Priority
These are correctness-preserving optimizations (same profit, fewer transfers). They can be done incrementally without breaking existing paths:

1. Verify existing patterns work with new encoding format first
2. Apply direct custody optimizations per path type
3. Each optimization should be tested against simulation before deployment
