## Problem
V2→V4 paths fail with CurrencyNotSettled because sync+settle for forward tokens weren't properly sequenced inside the callback.

## Resolution
The updated contract's Phase 0 auto-settles forward ERC-20 tokens when `t_queued_payload_index > 0` (meaning payloads were delivered before unlock). The Python encoder now includes `sync()` before the transfer to PM (before unlock), and Phase 0's `settle()` detects the balance increase. No explicit sync+settle payloads needed after unlock.

Verified by contract test `test_v2_v4_weth_to_usdc_usdc_to_weth` — 10/10 tests pass.

## Status: RESOLVED by contract update + Python encoder fix
