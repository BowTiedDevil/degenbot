## Problem

During `build_paths`, the Rust pump was running and processing blocks. Paths were eagerly solved via `register_and_solve_path`, but result batches accumulated in the engine's channel unprocessed. The main loop only started after `build_paths` returned, so 5+ minutes of solve results went unconsumed.

## Implementation (Concurrent task)

Extracted the main loop body into `consume_result_batches()`, an async coroutine that:
- Consumes result batches from `async for batch in engine_registry.engine`
- Dispatches profitable results via `dispatch_profitable_results()`
- Runs as a long-lived `asyncio.create_task` started BEFORE `build_paths`

In `main()`:
1. After pump resume, create the consumer task
2. Run `build_paths()` concurrently — it yields at `await asyncio.sleep(0)` so the consumer gets scheduled
3. After `build_paths` completes, `await result_consumer_task` to block indefinitely (the consumer IS the main loop)

Also added `#[must_use]` to `build_backfill_filter` (clippy-driven).

## Acceptance Criteria

- [x] Profitable results are dispatched during `build_paths`, not only after it completes.
- [x] No regression in path registration throughput.
- [x] `build_paths` still completes before the main loop's block-header subscription logic takes over.
- [x] Bot starts and runs successfully end-to-end.
