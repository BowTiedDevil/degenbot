## Problem

In the general multi-hop CL path solver (`int_solve_cl_path` for 3+ hops), `base_ranges` is cloned once and `crossings: Vec<Option<IntTickRangeCrossing>>` is allocated per candidate in the mixed-radix enumeration loop. The hot path (2-hop CL-CL) delegates to `int_solve_v3_v3` which avoids this. Only 3+ hop CL paths are affected, which are rare but present.

Location: `rust/src/optimizers/mobius_v3_int.rs` → `int_solve_cl_path` (~line 744)

## Fix

Pre-allocate `crossings` outside the enumeration loop and reuse with `clear()` / overwrite in-place each iteration. Avoid the `Vec::with_capacity(n_hops)` per candidate.

## Current Code Pattern

```rust
'outer: loop {
    let mut crossings: Vec<Option<IntTickRangeCrossing>> = Vec::with_capacity(n_hops);  // ← per candidate
    // ...
    let sim = int_simulate_cl_path_n(candidate, &crossings, &base_ranges);
    // ...
}
```
