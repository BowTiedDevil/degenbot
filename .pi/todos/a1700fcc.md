## Implementation Complete

### Changes
1. **`rust/src/optimizers/mobius_v3_int.rs`**:
   - Added `int_simulate_cl_path_n()` — N-hop CL path simulator that generalizes `int_simulate_v3_v3_path()` from 2 hops to N hops
   - Added `int_solve_cl_path()` — N-hop CL solver that generalizes `int_solve_v3_v3()` from 2 sequences to N sequences, using mixed-radix enumeration for crossing combinations (delegates to `int_solve_v3_v3` for the 2-hop case)
   - Added `int_simulate_mixed_path_n()` — N-hop mixed V2+CL path simulator
   - Added `exact_solve_mixed_path_n()` — N-hop mixed V2+CL solver that generalizes the existing 2-hop mixed solver to 3+ hops (delegates to `exact_solve_mixed_v2_v3_sequence` for the 2-hop case)
   - Added 9 new unit tests covering the new functions

2. **`rust/src/optimizers/uniswap_engine.rs`**:
   - Updated `solve_path()` CL dispatch from `if int_sequences.len() == 2` to `if int_sequences.len() >= 2`, calling `int_solve_cl_path()` instead of `int_solve_v3_v3()` directly
   - Updated `solve_mixed_path_int()` from `if resolved.hop_types.len() != 2 { return None; }` to handling N hops, calling `exact_solve_mixed_path_n()` for mixed paths
   - Added 2 integration tests: `solve_3hop_v3_v3_v3_path` and `solve_3hop_mixed_v2_v3_v2_path`

### Algorithm
For N-hop CL paths, the solver:
1. Fast path: all single-range sequences → flat `IntHopState` list → `exact_mobius_solve` (no crossing enumeration)
2. General case: enumerate (k0, k1, ..., k_{n-1}) ending-range combinations using mixed-radix counting
3. For each combination: build flat `IntHopState` list → `exact_mobius_solve` → total_optimal_input = crossing_cost + piecewise_optimal_input → validate with `int_simulate_cl_path_n` → search ±2
4. For 3 hops with 10 candidate ranges each: max 1000 combinations — feasible for the solver
