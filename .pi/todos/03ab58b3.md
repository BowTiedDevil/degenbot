## Decision: Not worth extracting

After implementation of Candidate #2 (decompose UniswapEngine), both `apply_log` and `process_backfill_logs` are in the same file (`event_routing.rs`, ~304 lines). The 6-branch if-chains are:

1. **Already readable** — clear topic-decode-dispatch pattern, ~50 lines each
2. **Different side effects** — `apply_log` marks dirty sets; `process_backfill_logs` tracks v3_touched/v4_touched flags and rebuilds. Unification would require a mode enum that complicates each handler
3. **V2 is only in apply_log** — backfill doesn't handle V2 Sync events at all, so the "6 entries" is really 5 vs 6
4. **Function pointer overhead** — `fn(&mut UniswapEngine, ...)` requires all handlers to have the same signature; the V3 mint/burn negation and V4 I256→i128 conversion are different enough that handler functions would need match-ons-DispatchMode internally, defeating the purpose
5. **Static dispatch is idiomatic Rust** — the compiler can inline and optimize the if-chain; a vtable or function pointer table would be slower

The cost/benefit doesn't justify the added abstraction layer. The current code is clear, localized, and fast.\n
