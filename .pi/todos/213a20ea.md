## Delivered (Option A — seam in isolation)

Slice 4 landed the `LogDispatcher` + `PoolStateSubscriber` trait + 6 Uniswap decoders + `EngineSubscriber` adapter + `Bot.attach_engine`/`dispatch_log` wiring, all exercised by 4 unit tests (2 dispatcher ordering/dead-subscriber + 2 adapter forward/dropped-engine). The live `apply_log` hot loop is untouched (slice 5 relocates the pump to drive `Bot.dispatch_log` directly — rewiring through `engine.apply_log` would self-notify under the engine's non-reentrant `Mutex` = deadlock).

### Files
- `rust/src/bot_core/log_dispatcher.rs` (new) — `LogDispatcher`, `PoolStateSubscriber` trait, `LogDecoder` trait, `DecodedPoolEvent` enum (6 variants), 5 decoder structs (V2Sync, V3Swap, V3MintBurn, V4Swap, V4ModifyLiquidity), `with_uniswap_decoders()` constructor, `dispatch()` (decode→apply→release-write-guard→notify), 2 tests.
- `rust/src/optimizers/uniswap_engine/engine_subscriber.rs` (new) — `EngineSubscriber` adapter wrapping `Weak<Mutex<UniswapEngine>>`, `weak_handle()` convenience, `on_pool_state_updated` → `engine.lock().insert_dirty(pool_id)`, 2 tests.
- `rust/src/bot_core/mod.rs` — `Bot.dispatcher` field, `dispatch_log()`, `attach_engine()`; `mod log_dispatcher` registered.
- `rust/src/optimizers/uniswap_engine/event_routing.rs` — `insert_dirty(pool_id)` (classifies via `core.read()` → v2/v3/v4 dirty set).
- `rust/src/optimizers/uniswap_engine/mod.rs` — `mod engine_subscriber`, `#[cfg(test)]` dirty-set accessors.

### Design decisions
- **Interior mutability on subscribers** (`parking_lot::Mutex<HashMap>`): decoders frozen at construction (plain `Vec`), subscribers runtime-mutable. Both `subscribe` + `dispatch` take `&self` so `Bot` (shared across threads) doesn't need `&mut`.
- **Lock order (D2) preserved by not nesting**: `dispatch` acquires the `BotState` write guard, applies, RELEASES, then notifies. The `EngineSubscriber` takes only the engine `Mutex` (core write already free); `insert_dirty` takes a core *read* guard (engine-then-core-read = same order as `apply_log`).
- **`Weak<dyn PoolStateSubscriber>`**: de-registered engines are silently skipped (no leak, no panic). The adapter double-guards the upgrade race.
- **`DecodedPoolEvent::apply` returns `Option<u64>`** (pool_id) — the family is re-derived by `insert_dirty` via `BotState` lookups (mirrors `derive_hop_type`), so the dispatcher stays family-agnostic.
