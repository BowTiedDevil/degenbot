**Master: `TODO-215e9e66` (ADR-006).** Deps: slice 3. Addresses ADR-006 D4 (the event bus + subscriber seam).

**Goal.** Introduce the per-state-subject publisher/subscriber event bus. A `LogDispatcher` helper on `Bot` owns a decoder registry + a `Weak<dyn PoolStateSubscriber>` registry; pool-state events are decoded and applied to `BotState` by `Bot` itself (the state owner decodes the events that mutate its owned state — decode follows the state); after the core write lock releases, `LogDispatcher` notifies subscribers per `pool_id` (bare, shape (i) — Q7 resolved). The engine implements `PoolStateSubscriber` and dirties `pool_id` in its **own** dirty-set (taking the engine `Mutex` alone — core write already released — D2's engine-then-core order preserved).

**Rust work.**
- New `rust/src/bot_core/log_dispatcher.rs` (or under a `bot_core/` subpath) — `pub(crate) struct LogDispatcher`:
  - `decoders: Vec<Box<dyn LogDecoder>>` — a `LogDecoder` trait: `fn try_decode(&self, log: &Log) -> Option<DecodedEvent>` (V2/V3/V4 decoders register here; future Curve/Aave decoders plug in without Bot knowledge). Move/invite the existing decoders (`v2_sync_decoder.rs`, `v3_swap_decoder.rs`, `v3_mint_burn_decoder.rs`, `v4_swap_decoder.rs`, `v4_modify_liquidity_decoder.rs`) under this registry shape.
  - `subscribers: HashMap<u64, Vec<Weak<dyn PoolStateSubscriber>>>` keyed by `pool_id` — Bot mediates the registry (cleaner than per-`PoolEntry` callback Vecs in Rust).
  - `dispatch(&self, log, bot_state: &Arc<RwLock<BotState>>)` → decode → `bot_state.write().apply_*(decoded)` → **release write guard** → for each subscriber of the affected `pool_id`: `upgrade()` (skip dead) → `subscriber.on_pool_state_updated(pool_id)`.
- New trait `rust/src/bot_core/subscriber.rs` (or `event_sink.rs`):
  ```rust
  pub trait PoolStateSubscriber: Send + Sync {
      fn on_pool_state_updated(&self, pool_id: u64);
  }
  ```
  Ships as `PoolStateSubscriber` (honest name) until a second state-subject type proves generality (then rename to `StateSubscriber`). No separate `on_reorg` method (slice 7 makes reorg a burst of this).
- The engine: implement `PoolStateSubscriber` for a thin adapter around `Arc<Mutex<UniswapEngine>>` (e.g. `struct EngineSubscriber(Arc<Mutex<UniswapEngine>>); impl PoolStateSubscriber for EngineSubscriber { fn on_pool_state_updated(&self, pool_id) { self.0.lock().insert_dirty(pool_id) } }`). The `insert_dirty` (or expose the existing dirty-insert) must take ONLY the engine `Mutex` (no core lock) — keeps D2 order.
- `Bot::attach_engine(engine)` (slice 3's placeholder): when a path is registered against the engine, the engine subscribes its listener to each `pool_id` in the path via `log_dispatcher.subscribe(pool_id, Arc::downgrade(&engine_listener))`.

**Tests (red/green TDD).**
- `LogDispatcher`-in-isolation: give it a fake `BotState` + a registered fake decoder; push a log; assert the decoder fired, `apply_*` ran, subscribers notified AFTER the write guard released (assert via a subscriber that records the call ordering vs a fake state-read).
- Dead-subscriber handling: drop an engine subscriber, push a log, assert no panic (Weak `upgrade()`→None skipped).
- Lock-order test: subscriber's handler must not acquire the core lock synchronously (assert via a subscriber that probes the core lock — should not block/contend during notify).
- Engine-side: `on_pool_state_updated` dirties `pool_id` in the engine's dirty-set; solve at the (slice-6) drain tick reads it.

**Out of scope here.** The pump driving the dispatcher (slice 5); the drain-trigger solve tick (slice 6); reorg (slice 7). This slice delivers the bus + the subscriber seam + wiring between `BotState` mutation and notify.

**Acceptance.** `just test-all` green; `PoolStateSubscriber` trait + `LogDispatcher` exist as `pub(crate)` helpers with their own tests; the engine implements the subscriber; pool-state decode+apply+notify flows through `LogDispatcher`; engine's `apply_log` per-event path (today, in `event_routing.rs`) is REPLACED by the dispatcher-driven path for engines that subscribe. The engine decodes nothing and touches no core lock at notify.
