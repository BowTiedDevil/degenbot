## What (per the slice-5 todo candidate-2 finding)
The pure-logic helpers in `rust/src/optimizers/uniswap_engine/py_binding.rs`:
- `SnapshotStore<K>` (the generic one-way tick-data store: `load`/`take`/`insert`)
- `register_with_cl_buffers` logic (the CL pool registration: snapshot tick_data → apply backfill buffer → apply pump buffer, in two staged steps under the engine lock)
- verify-plumbing (`verify_on_register` flow: capture raw tick_data pre-buffer + post-backfill snapshots, run RPC verification outside the lock, RuntimeError on mismatch)

These are entangled with PyO3 (`Py<PyBot>`, PyResult, `Bound<PyList>` arg parsing) but the CORE logic is pure (no pyo3). ADR-006 D4 candidate-2 finding: lift the pure core into its own module (e.g. `rust/src/optimizers/uniswap_engine/snapshot_verify.rs` or `bot_core`) with a clean typed API, leaving py_binding.rs as a thin PyO3 adapter.

## Scope
- Extract the snapshot store + two-phase verify into a new module with a typed input (frozen dataclass-style), no PyResult/pyo3.
- RED: unit tests for the staged buffer application (`apply_backfill_buffer` then `apply_pump_buffer`) + snapshot capture + verify mismatch (all without a live RPC — fake the on-chain reads).
