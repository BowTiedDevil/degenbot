## Problem

`filter_relevant_logs` clones all passing logs. Same issue as process_backfill_logs — `Log` is a large struct (~200+ bytes). Called on every backfill range.

Location: `rust/src/optimizers/uniswap_engine_pump.rs` → `filter_relevant_logs` (~line 825)

## Fix

Return indices or references instead of owned `Vec<Log>`. Or pass the full slice to the engine and let it skip irrelevant logs (it already does in `apply_log`). The engine's `process_block` and `apply_log` both iterate the full slice and skip irrelevant topics, so `filter_relevant_logs` could be eliminated for the eager path entirely — just pass the raw WS logs directly.

## Current Code Pattern

```rust
pub fn filter_relevant_logs(logs: &[Log], relevant_topic_set: &HashSet<B256>) -> Vec<Log> {
    logs.iter()
        .filter(|log| ...)
        .cloned()  // ← clones every passing Log
        .collect()
}
```
