## Context
The bot running at `/tmp/bot-run-v5.log` shows three categories of simulation failures during `dispatch_profitable_results`. These are **not** encoding exceptions (those are fixed — the log now shows `0 exceptions`). These are on-chain revert failures surfaced at INFO level via the `_sim_log()` budget.

## Failure Patterns (from `/tmp/bot-run-v5.log`)

### 1. `CurrencyNotSettled()` — V3→V3→V4 and V3→V4→V3 paths
```
[sim-fail] path=8 V3-V3-V4: call[3] failed (gasUsed=239178) revert=0x5212cba1 CurrencyNotSettled()
[sim-fail] path=987 V3-V4-V3: call[3] failed (gasUsed=250144) revert=0x5212cba1 CurrencyNotSettled()
```
This suggests the V4 settlement sequence inside `unlockCallback` is not correctly settling all currency deltas before the callback returns. Likely causes:
- Missing `V4_SETTLE` or `V4_SETTLE_DELTA` for the V4 input currency
- Wrong currency index being settled (native ETH vs WETH confusion)
- Pool order matters: V4 as middle hop vs V4 as last hop may need different settlement logic

### 2. `TF` (Transfer Failed) — V3→V3→V3 paths
```
[sim-fail] path=1700 V3-V3-V3: call[3] failed (gasUsed=508321) revert=0x08c379a0... "TF"
```
The V3 flash-swap callback tries to transfer WETH to the first V3 pool, but the executor doesn't hold enough WETH. This is expected for 3-hop V3-only paths since there's no WETH prefunding — but the solver predicted profit, so either:
- The solver overestimates (tick data stale)
- The WETH auto-pay logic in the executor is wrong for 3-hop chains
- `_3hop_v3_v3_v3` encoder is missing a step

### 3. `IIA` (Insufficient Input Amount) — V3→V3→V3 paths
```
[sim-fail] path=55843 V3-V3-V3: call[3] failed (gasUsed=278934) revert=0x08c379a0... "IIA"
```
V3 callback receives less input than expected. For 3-hop V3 chains, the intermediate V3 swap output must arrive at the next pool BEFORE its callback executes. The `_3hop_v3_v3_v3` encoder may have the wrong call sequence inside the callback.

### 4. `ERC20: transfer amount exceeds balance` — V3→V4→V3 paths (sel=0x90bfb865)
```
[sim-fail] path=45302 V3-V4-V3: call[3] failed (gasUsed=227244) revert=0x90bfb865... sel=0x90bfb865
```
This is an ERC-20 transfer revert. Decoder for `0x90bfb865` may be a wrapped panic or custom error. Need to trace what transfer is failing.
