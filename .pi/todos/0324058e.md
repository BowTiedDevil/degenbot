Implement reorg detection and rollback at the optimizer engine level (V2BlockEngine, V3BlockEngine, V4BlockEngine, UniswapEngine).

Scope:
- Detect reorgs (e.g., block number regression, parent hash mismatch from WS subscription)
- Use the existing `ReorgJournal` infrastructure from `bot_core/state_history.rs` (already has `V2BlockDelta`, `V3BlockDelta`, `TickBefore`, `push_delta`, `restore_before_block`)
- Integrate `ReorgJournal` into the optimizer sub-engines (currently only used in `bot_core`)
- Write tests simulating reorg scenarios within the buffered event window:
  - Reorg that invalidates a buffered Mint event → buffer must unwind
  - Reorg that reverts a Swap → pool state must restore from journal
  - Reorg during the pump's subscribe phase → buffered events must be discarded/rebuilt
  - Multi-block deep reorg (e.g., 3 blocks undone)

**Dependencies**: Raw-event buffer design supports reorg unwind as a future addition. NOT on the critical path for rolling-start.
