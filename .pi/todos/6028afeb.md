Refactor the Python bot example (`eth_backrun_v2_v3_v4_rust.py`) to implement rolling start:

**New startup sequence**:
1. Call `engine.subscribe(ws_url)` immediately — WS live, Mint/Burn events buffered
2. Observe first block from subscription → `backfill_to_block`
3. Begin path loading via `find_paths_async` (can start before backfill completes)
4. Run backfill to `backfill_to_block` (no gap between backfill and pump's resume point)
5. Run per-pool verification (not first-failure-stop)
6. Call `engine.resume()` — pump begins processing from `backfill_to_block + 1`
7. Continue path loading in background via `register_and_solve_path`
8. Main loop runs concurrently — dispatches profitable results as paths come online

**Key changes**:
- `build_paths()` splits into seed loading + background `asyncio.Task`
- `EngineRegistry.register_path()` branches on whether engine is running: if not, use `register_path`; if running, use `register_and_solve_path`
- Backfill target comes from `subscribe()` return value, not a separate `get_block("latest")` call
- `verify_liquidity_maps` stays, runs per-pool for full error report
- Python key dicts (`_v2_keys`, etc.) remain plain dicts — add note that methods are not thread-safe
- `freeze()` and `initial_solve()` calls removed
