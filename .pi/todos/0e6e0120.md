## Summary
Update the simulation pipeline in `dispatch_profitable_results()` / `simulate_one()` to properly interact with the new cmd_executor's profit check mechanism and ERC6909 balance tracking.

## Current Simulation Pattern (7 calls)
```
1. WETH.balanceOf(executor) — before
2. Multicall3.getEthBalance(executor) — before
3. PM.balanceOf(executor, weth_id) — ERC6909 before
4. execute(commands)  ← Missing expected_balance parameter!
5. WETH.balanceOf(executor) — after
6. Multicall3.getEthBalance(executor) — after
7. PM.balanceOf(executor, weth_id) — ERC6909 after
```

## New Simulation Pattern
```
1. WETH.balanceOf(executor) — before
2. Multicall3.getEthBalance(executor) — before
3. PM.balanceOf(executor, weth_id) — ERC6909 before
4. execute(commands, expected_balance)  ← With packed profit check
5. WETH.balanceOf(executor) — after (for off-chain profit measurement)
6. Multicall3.getEthBalance(executor) — after
7. PM.balanceOf(executor, weth_id) — ERC6909 after
```

### Key Changes

#### 1. Build expected_balance Before Simulation
The expected_balance must be computed from the pre-tx balance reads (calls 1-3):
```python
# After decoding calls[0]-[2]:
weth_before = int.from_bytes(calls[0]["returnData"], "big")
eth_before = int.from_bytes(calls[1]["returnData"], "big")
erc6909_before = int.from_bytes(calls[2]["returnData"], "big")

# Choose mode based on path type
if path_type_is_pure_v4_with_mint:
    expected_balance = (2 << 248) | erc6909_before
else:
    combined_before = weth_before + eth_before
    expected_balance = (1 << 248) | combined_before
```

#### 2. Two-Pass Simulation (Problem)
We need the pre-tx balances BEFORE constructing the execute() calldata, but the simulation reads them IN the same batch. Options:
- **Option A**: Fetch pre-tx balances in a separate RPC call before the simulation batch
- **Option B**: Use expected_balance=0 (mode 0, skip check) for simulation, use real expected_balance only for on-chain submission
- **Option C**: Fetch pre-tx balances once per dispatch block (same for all paths) and reuse

**Recommended**: Option C — fetch pre-tx balances once at the start of `dispatch_profitable_results()` and reuse across all `simulate_one()` calls within that dispatch. The pre-tx balance doesn't change between paths in the same block.

#### 3. Update Profit Measurement
Post-simulation profit calculation remains the same:
```python
combined_before = weth_before + eth_before + erc6909_before
combined_after = weth_after + eth_after + erc6909_after
gross_profit = combined_after - combined_before
```

#### 4. Submit with Real expected_balance
When submitting a real transaction (not simulation), use the actual on-chain pre-tx balance:
```python
# Fetch current pre-tx balance
pre_tx_weth_eth = await async_w3.eth.call(...)  # Single call
expected_balance = (1 << 248) | pre_tx_weth_eth

# Build final calldata
selector = web3.Web3.keccak(text="execute(bytes,uint256)")[:4]
calldata = selector + eth_abi.abi.encode(
    types=["bytes", "uint256"],
    args=[cmd_bytes, expected_balance],
)
```
