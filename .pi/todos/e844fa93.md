## Problem
`uniswap_engine.rs` is 4902 lines carrying six distinct responsibilities: PyO3 deserialization, engine lifecycle, event routing, solver dispatch, result diff/channel logic, and ~125 tests. All in one file. A change to PyO3 tuple parsing requires navigating past solver math.

## Files
- `rust/src/optimizers/uniswap_engine.rs` (4902 lines — all of it)

## Design
Split into domain-aligned submodules under a `uniswap_engine/` directory. The struct and its state live in `mod.rs`; methods move to the module that owns the concern. Rust allows `impl UniswapEngine` blocks across files within the same crate.

### Proposed module split

| Module | Contents | Approx lines |
|--------|----------|-------------|
| `mod.rs` | `UniswapEngine` struct, `new()`, public re-exports, `SolvePathResult`, `ResultBatch`, `BlockMetadata`, `HopType`, `MixedPoolRef`, `EnginePhase`, `PoolTickCoverage` | ~500 |
| `event_routing.rs` | `apply_log()`, `process_backfill_logs()`, `process_block()`, `process_updates()`, `process_v4_updates()`, `process_all_updates()` | ~400 |
| `solver_dispatch.rs` | `resolve_path()`, `solve_path()`, `solve_mixed_path_int()`, `solve_all()`, `rebuild_and_solve_affected()`, `solve_dirty()`, `IntHopStateExt` trait | ~600 |
| `result_channel.rs` | `compute_diff_and_send()`, `send_result_batch()`, `set_result_channel()`, `set_profit_thresholds()`, `delivered`/`deregistered`/`pending_new_paths` logic | ~300 |
| `lifecycle.rs` | `solve_all_paths()`, `register_path()`, `register_and_solve_path()`, `deregister_path()`, `set_event_buffer_max_age()`, `flush_event_buffer()`, `set_last_processed_block()`, `latest_results()`, pool/v2/v3/v4 count accessors | ~400 |
| `py_binding.rs` | `PyUniswapArbEngine` struct, all `#[pymethods]`, `parse_v2_updates`, `parse_v3_updates`, `parse_v4_updates`, `parse_tick_priors`, snapshot deserialization, verification orchestration, `__anext__` | ~2200 |
| `tests/` | All 125 test functions (can be split further by concern: v2_paths, v3_paths, mixed_paths, result_diff, etc.) | ~500 |

### Approach
1. Create `rust/src/optimizers/uniswap_engine/` directory
2. Move current `uniswap_engine.rs` → `uniswap_engine/mod.rs`
3. Extract one module at a time, running `just test-rust` after each
4. Start with the simplest extraction: `result_channel.rs` (self-contained, no cross-dependencies)
5. Then `event_routing.rs` (depends on the struct + dirty sets)
6. Then `solver_dispatch.rs`
7. Then `lifecycle.rs`
8. Then `py_binding.rs` (move all PyO3 code)
9. Finally move tests to `tests/`

### Key constraints
- `impl UniswapEngine` blocks can span files in the same crate — no architecture change needed, just file splits
- `impl PyUniswapArbEngine` must stay with `#[pymethods]` — moves wholesale to `py_binding.rs`
- Re-export public types from `mod.rs` so external import paths don't change

## Dependencies
- Independent of other candidates — can be done first or in parallel

## Effort
Medium — mechanical file splits, no logic changes. ~1 day of careful extraction + test runs.
