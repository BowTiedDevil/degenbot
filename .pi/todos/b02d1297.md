## Problem
One V4-V4 path (15381) fails with `SafeCastOverflow` (0x93dafdf1) — amount exceeds int128 range.

## Resolution
The `fits_int128()` guard already exists in `encode_v4v4_payloads` and all other V4 encoders. The guard checks both `-optimal_input` and `-output_a` before constructing swap params, skipping paths that would overflow. This path should now be silently skipped.

If the path still shows up as a simulation failure, it means the overflow happens at on-chain delta accumulation (not at amount_specified encoding), which would require either: (a) a different overflow guard in the contract, or (b) additional checks in the Python encoder for cumulative delta size post-swap.

## Status: MITIGATED. The fits_int128() guard should skip this path. Needs mainnet testing to confirm.
