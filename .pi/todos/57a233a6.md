3 test failures.

**1. V3 liquidity_math `test_add_delta`**: `OverflowError: can't convert negative int to unsigned`

The Rust `cl_add_delta` accepts `liquidity: i128, delta: i128`. The Python test passes negative values that overflow `i128`. Need to change the PyO3 signature to accept `&Bound<'_, PyAny>` and use `extract_i256` + `i128::from_be_bytes` (same pattern as `cl_compute_swap_step_v3`).

**2. V3 sqrt_price_math `test_get_next_sqrt_price_from_input` and `test_get_next_sqrt_price_from_output`**:

- `get_next_sqrt_price_from_input` — expects `required: sqrt_price_x96 > 0` but gets `InvalidPrice`
- `get_next_sqrt_price_from_output` — expects `required: denominator > 0` but gets `DIVISION BY ZERO`

V3 Python has descriptive error messages (e.g. `required: sqrt_price_x96 > 0`) while Rust `ClMathError` uses generic names (`InvalidPrice`, `DivisionByZero`). The V3 sqrt_price_math wrapper needs message translation.

**Fix**:
- For `add_delta`: change PyO3 params to `&Bound<'_, PyAny>` with `extract_i256`
- For V3 sqrt_price_math: translate error messages in the Python wrapper layer
