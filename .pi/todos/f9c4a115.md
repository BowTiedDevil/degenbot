**Slice 14 of the Polars three-layer migration (ADR-005, deferred target).** Master: `TODO-7e24d695`. Deps: slice 13 (crate split; `PyBotIo` lives in `degenbot-python`).

**Goal.** Port the stateful I/O (RPC provider / DB session) to Rust as a `#[pyclass]` `PyBotIo` (stateful, holds provider/DB refs), so the `Bot` orchestration can move to Rust. Per ADR-005, naming follows `Py + *Io`/`*Reader`. This is the last step toward a pure-Rust bot (a Rust consumer using `degenbot-core` + a Rust-native I/O struct — though `PyBotIo` itself is Python-facing; the standalone Rust I/O is a further step beyond this slice).

**Rust (new).** `degenbot-python` `bot_io.rs` (or `py_bot_io.rs`):
- `PyBotIo` `#[pyclass]` holding provider/DB handles (the `ProviderAdapter`/`DatabaseSessionManager` equivalents in Rust).
- Methods for the builder I/O choreography (DB lookup → RPC fetch → decode → construct) currently in Python builders' `build()`/`update()` — moved here, called from Python via `PyBotIo`.
- Reuses the existing `AsyncProviderAdapter`/`SyncProviderAdapter` Rust seams (the `provider/` module split).

**Python.** `Bot` delegates I/O to `PyBotIo` instead of doing it inline; the Python `Bot` shrinks to config + orchestration (which providers, which DBs, chain config, result dispatch). Builders' `build()`/`update()` become thin callers of `PyBotIo` methods (the I/O choreography moves; the construction logic — wrap-with-companion — stays Python until the pure-Rust-bot step).

**Tests.** I/O round-trip tests (DB pool lookup, ERC20 metadata RPC fetch, decode, construct-companion); provider/DB mock tests; the `PyBotIo` surface mirrors the `BuilderContext` dependencies (`db`/`erc20_builder`/`default_chain_id`/`managed_pools`).

**Consistency at boundary.** `Bot.build_pool` / `build_erc20token` / `build_managed_pool` end-to-end green via `PyBotIo` (same observable behavior). The pure-Rust-bot target becomes reachable (a Rust consumer using `degenbot-core` + a `PyBotIo`-equivalent Rust I/O struct — the standalone Rust I/O is a further step, not this slice).

**Acceptance.** `cargo`/`ruff`/`ty` green; I/O round-trip tests pass; `Bot.build_pool` via `PyBotIo` matches pre-migration behavior; the Python `Bot`'s inline I/O code is gone (delegated to `PyBotIo`).
