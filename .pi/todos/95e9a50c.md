When `Mint`/`Burn` events arrive for a pool not yet registered, buffer the raw events in the appropriate sub-engine (V3 or V4) keyed by pool identifier (V3: contract address, V4: pool_manager + pool_id).

When a pool is later registered:
1. Claim any buffered events for that pool
2. Apply them to the pool's tick data eagerly (during `register_pool`, under the same lock)
3. Remove the buffer entry for that pool

The buffer stores raw events (not collapsed/incremental) to support future reorg handling.

**Decisions**:
- Buffering lives in the sub-engines (V3BlockEngine, V4BlockEngine), routed by topic identity markers immediately upon receipt
- Raw events stored, not collapsed tick deltas (reorg-safe)
- Events are applied eagerly at pool registration time (under the same lock as registration)
- `Swap`/`Sync` events for unregistered pools are safely discarded (stateless, registration state is current)
- V2 has no buffering need (Sync is stateless, reserves come from registration)
