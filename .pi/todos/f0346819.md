## Completed Changes

### 1. `int_simulate_v3_swap` now returns `V3SwapResult` (consumed_input + output)

New struct:
```rust
pub struct V3SwapResult {
    pub consumed_input: U256,  // Gross input actually consumed (including fees)
    pub output: U256,           // Swap output amount
}
```

When the range boundary is hit, `consumed_input < amount_in` — matching V3's on-chain behavior where `amountSpecified - amountSpecifiedRemaining` tracks the unused portion. The consumed input is computed from the range boundary output:
- zfo: `net_consumed = L * 2^96 * (sp_current - sp_lower) / (sp_current * sp_lower)`
- ofz: `net_consumed = L * (sp_upper - sp_current) / 2^96`
- Both: `gross_consumed = net_consumed * fee_denom / gamma_numer`

When the range is NOT hit, `consumed_input == amount_in` (full input consumed).

### 2. `SimulationResult` includes `consumed_inputs: Vec<U256>`

Each element tracks the gross input consumed by that hop. For V2 hops, `consumed_inputs[i] == amount_in` (constant-product always consumes full input). For V3/V4, it may be less on partial fills.

### 3. `SolvePathResult` includes `consumed_inputs: Vec<U256>`

`profit` is now computed as `final_output - consumed_inputs[0]` for CL paths (matching on-chain behavior where unused input is returned to the caller).

### 4. V4 int128 guard in `solve_path()`

After solving, the engine checks whether any V4 hop's `consumed_input` or `hop_output` exceeds `INT128_MAX` (0xFFFFFFFFFFFFFFFF_FFFFFFFFFFFFFFFF). If so, the path is rejected — V4's `toBalanceDelta()` would revert with `SafeCastOverflow`.

This eliminates phantom profits from paths like V3 XOR→V4 where the V3 output (~8.3×10⁴⁵) exceeds int128_max (~1.7×10³⁸).

### 5. Python `latest_results` includes `consumed_inputs`

The result tuple is now `(path_id, optimal_input, profit, hop_outputs, consumed_inputs)`. All Python callers (dispatch loop, focused script, tests) updated.

### 6. Tests

- Updated existing `int_simulate_v3_swap` tests to assert `consumed_input == amount_in` for non-boundary cases
- Added `v4_int128_overflow_path_rejected` test in `uniswap_engine.rs`
- Updated Python test `test_pure_v2_path_finds_arb` to unpack 5-element result
