## Decision: (a) Accept + Document ✅

The empty-metadata send paths are **proven unreachable for profitable results**; the gap-backfill path doesn't send at all. No behavioral risk today. `next_base_fee(0,0,0)=0` is safe (no div-by-zero). Documentation delivered; the cheap hardening filed as follow-up `TODO-3ff0689d`.

## Full analysis (verified by tracing the pump loop + Python consumer)

### The Python consumer (`examples/eth_backrun_v2_v3_v4_rust.py:2196`)
- `block_number = batch["solve_block"]` — **correct** even on backfill (real block number passed through; only metadata is zero).
- `base_fee = batch.get("base_fee_per_gas") or 0` — handles `None` (default) → 0. Safe.
- `gas_used`/`gas_limit` → 0 on default-metadata batches.
- `base_fee_next = next_base_fee(parent_base_fee=0, parent_gas_used=0, parent_gas_limit=0)` (`evm_math.next_base_fee`): `last_gas_target = 0//2 = 0`, `gas_used(0) == gas_target(0)` → returns `parent_base_fee = 0`. **No div-by-zero, no exception.**
- Submission (`:2128`): `tx_params["maxFeePerGas"] = int(1.5 * base_fee_next) + priority_fee`. With `base_fee_next=0` → `maxFeePerGas = priority_fee` ≪ real block base fee → **underpriced tx, dropped from mempool** (no crash; opportunity silently wasted).
- Cosmetic: `latency = time.time() - block_timestamp(=0)` ≈ 1.7e9 → absurd `[+1700000000.0s]` log line. Nuisance only.

### Why no profitable batch ever reaches dispatch with zero metadata
1. `solve_all_paths` (`lifecycle.rs:143` → `compute_diff_and_send(&BlockMetadata::default())`) — **no Python callers** (grep-verified). Vestigial (corroborates the dead `has_unsent_results` field: the immediate-dispatch design was abandoned for pump-driven rolling start). **Unreachable.**
2. `finalize_if_dirty` send (`pump:700`, `&BlockMetadata::default()`) — guarded by `if block > *last_solved_block`. The pump loop runs `solve_dirty` (which clears `dirty` + sets `last_solved_block = current_block`) at the **top of every iteration before awaiting the next event**, so at any `finalize_if_dirty(old_block)` call `old_block == last_solved_block` → guard false → no send. Profitable results instead flow through the debounce `send_result_batch(&current_metadata)` (`:518`, `:550` — **real** metadata).
3. `finalize_if_dirty` else-branch `process_block_and_send(&[], ...)` (`pump:704`) — sends an **empty** batch (no `fresh`/`updated`) → `results` empty → `dispatch_profitable_results` not called. Cosmetic latency-log only.
4. `backfill_range` `process_block(... &BlockMetadata::default())` — `process_block` solves but **does not send**. Accumulated results piggyback onto the next debounce `send_result_batch` with real metadata.

### Latent sharp edge (documented at call sites)
A future refactor breaking EITHER (1) the "solve at loop top before await" invariant OR (2) the `block > last_solved_block` guard in `finalize_if_dirty` would let a profitable batch dispatch with `base_fee_next=0` → underpriced txs silently dropped → filed as `TODO-3ff0689d`.
