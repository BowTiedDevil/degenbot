Epic: `4ROQ6S` — "Bot deep, Python light, DB privileged". Dep `5DOF4C` (P4a) is
`done`. P3 (`c698aad1d`) shipped `PoolRef` + `Bot.pools_for_tokens` on the
graph-read seam (`build_path_graph` over `fetch_path_graph_edges`), whose kind

## What changed (files + intent)

### New — `rust/crates/shells/degenbot-python/src/db/discovery_read.rs`

- `PyDiscoveryPoolRow` (`#[pyclass(name = "DiscoveryPoolRow", module =
  "degenbot._ffi.db")]`) — the typed `degenbot_db::DiscoveryPoolRow` enum
  flattened across the three family variants into one uniform view: `kind`
  (raw polymorphic string), `family` (`"V2"`/`"V3"`/`"V4"`), `address` /
  `manager` / `pool_hash`, `token0` / `token1` (+ ids), `db_id`, `factory`,
  `fee` (`fee_token0` for V2/V3, `fee_currency0` for V4), `tick_spacing`,
  `stable`, `update_block` (the liquidity-update marker). Family-scoped fields
  are `None` where the family has no such column.
- `db_fetch_discovery_rows(database_path, chain_id) -> list[DiscoveryPoolRow]` —
  the READ seam over `DegenbotDb::fetch_discovery_rows`. Mirrors the sibling
  read seams: `database_path` + `chain_id` args, `py.detach()` around the DB
  I/O, `db_err_to_py` error mapping. READ exposure only — deliberately NOT
  behind the `writer` feature (ADR-070 gates only write-capable constructors).

### Changed — `rust/crates/shells/degenbot-python/src/db/mod.rs`

- `pub mod discovery_read;` + the `#[pymodule_export]` of
  `db_fetch_discovery_rows` / `PyDiscoveryPoolRow`.

### Changed — `src/degenbot/db/__init__.py`

- Re-export `db_fetch_discovery_rows` + `DiscoveryPoolRow` (the stable mirror).

### Changed — `src/degenbot/discovery.py`

- `pools_for_tokens` now does ONE `db_fetch_discovery_rows` read, projects the
  rows whose token pair matches into refs (ordered by `graph_id`), and applies
  the optional `pool_kinds` filter by mapping `row.family` through
  `FAMILY_TAG_TO_POOL_KIND`. The `build_path_graph` / `db_resolve_token_ids`
  imports are gone; the degree >= 2 cycle filter no longer applies.
- `_ref_from_edge` replaced by `_ref_from_row`: every kind param
  (`kind_string` / `factory` / `fee` / `tick_spacing` / `stable` /
  `update_block`) is filled from the row; `graph_id` is derived as
  `db_id + V4_POOL_ID_OFFSET` for V4 else `db_id` (the graph pairing is retired
  as the row read dictates). Module + `PoolRef` docstrings updated.

### Changed — `src/degenbot/_ffi/db.pyi`

- Regenerated by `just gen-stubs` (the new pyclass + pyfunction, `__all__`
  updated). Deterministic; the drift gate passes.

### Changed — `tests/database/test_pool_discovery.py`

- The fixture now stamps the V3 + V4 liquidity markers through the Rust apply
  seams so `update_block` is exercised.
- New: `test_pool_ref_kind_params_are_filled_from_the_discovery_read` (every
  kind param, incl. `fee`/`tick_spacing`/`stable`/`update_block`).
- New: `test_pools_for_tokens_discovers_a_degree_one_pair` (the cycle filter is
  lifted — a pair whose tokens each appear in one pool still discovers).
- New: `test_pools_for_tokens_reports_the_aerodrome_stable_flag` (the Aerodrome
  V2 `stable` subclass column reaches the ref).
- Existing identity / inertness / construction-ladder tests unchanged.
