# SH4SFK — Fixup: route the tick-fetch interval env read through degenbot-config

STATUS: **DONE.** Scoped gates green on the current tree; nothing PENDING.

The degenbot-config hygiene gate `no_stray_python_env_reads` failed on
`src/degenbot/builders/tick_data_fetcher.py:28`, which read
`DEGENBOT_TICK_FETCH_MIN_INTERVAL_MS` straight from `os.environ`. The preferred
route was taken: the knob is now a declared typed-config key and the fetcher
reads the installed verdict.

## What changed

- `rust/crates/foundation/degenbot-config/src/schema.rs`
  - Declared a new `builders BuildersConfig` section with
    `tick_fetch_min_interval_ms [ms] = 0`, env
    `DEGENBOT_TICK_FETCH_MIN_INTERVAL_MS`, TOML
    `builders.tick_fetch_min_interval_ms`. `SCHEMA` is the single declaration
    site; the env name and the `0`-disables default are identical to the
    retired read.
- `src/degenbot/builders/tick_data_fetcher.py`
  - Dropped `import os` and the module-level env read.
  - Added `_min_interval_seconds()`, which reads
    `resolved_config().values.builders.tick_fetch_min_interval_ms / 1000` (the
    `simulation.pipeline_concurrency` pattern: a named property off the typed
    seam projection).
  - Replaced the module-global governor state (`global _pace_next_free`) with a
    small `_TickFetchGovernor` class holding the lock and next-free instant;
    `_pace()` is now a thin wrapper. This was required in-scope: the pre-existing
    `global` statement and the new function's docstring tripped `ruff`
    (`global-statement` is only exempted under `src/degenbot/runner/**`,
    `D401`/`DOC201` are not), so the file could not pass its own lint gate as
    written. Behavior is unchanged.
- `tests/builders/test_tick_data_fetcher.py`
  - New `TestRateClampReadsTheTypedConfig`: `governed_holder` sets the env
    override, and the test asserts `_min_interval_seconds() == 0.02` and that
    two `_pace()` calls space by exactly `0.02` s (clock/lock faked). No prior
    test exercised the interval.
- `docs/rust-config-keys.md` — regenerated with
  `REGEN_CONFIG_DOCS=1 cargo test -p degenbot-config` (the writer is the gate).
- `rust/crates/foundation/degenbot-config/tests/degenbot_env_inventory.txt` —
  refreshed with `just env-inventory` (the committed snapshot fallback now
  carries the new key).
- `rust/crates/foundation/degenbot-config/tests/fixtures/config_parity/oracle.json`
  — regenerated by its own writer test on the schema change.
- `src/degenbot/_ffi/__init__.pyi` — regenerated with `just gen-stubs`
  (`ConfigValues.builders` + `_ConfigBuildersFace.tick_fetch_min_interval_ms`).

## Behavior

Unchanged at the default: the schema default is `0`, matching the retired
fallback, so the governor is a no-op unless the operator sets the key. The one
narrow difference is the parse: the old `float(...)` accepted a fractional ms
string; the declared `ms` kind is a `u64`, so a fractional value now fails the
load loudly instead of silently truncating. Same env name, same `0`-disables
semantics, read at use time from the one verdict rather than frozen at import.
