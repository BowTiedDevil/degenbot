How the Möbius solver prices a path through a concentrated-liquidity hop

A tick range of a V3/V4 pool is a bounded-product CFMM with virtual reserves R₀+α = L·2⁹⁶/√P, R₁+β = L·√P/2⁹⁶. The solver turns each possible ending tick range into exactly one Möbius piece of the path, finds each piece's argmax in closed integer form, then reaches the global argmax with a monotone active-set walk instead of enumerating ending-range tuples. All math below runs live in BigInt, mirroring degenbot-solvers.

1 · One tick range ⇒ one CP piece

Inside a range the pool swaps like constant-product; crossing a boundary switches liquidity, so the hop's curve is a staircase of CP pieces.

per piece k (input g = x − C_k): net = ⌊g·γ/FD⌋ s = L·2⁹⁶·S / (net·S + L·2⁹⁶) out = F_k + ⌊L·(S−s)/2⁹⁶⌋

C_k/F_k come from the precomputed crossing table (int_v3_hop.rs, cl/crossings.rs): gross input to traverse ranges < k and the output they pay.

2 · Each piece is exactly Möbius

Composing CP maps stays CP (SL(2) closure); crossing translations just shift the matrix. So per piece — for a chain of ANY length mixing V2 and V3 pools — the whole path is one rational function parameterized by the ending-range tuple of its V3 hops.

O(x) = (a·x + b) / (c·x + d) argmax of P(x) = O(x) − x: x* = (⌊√(a·d − b·c)⌋ − d) / c

mobius_shifted_piece.rs builds the matrix; mobius_int_exact.rs does the same for pure-V2 paths.

3 · Active-set walk, no enumeration

P is concave and C¹ across pieces, so the landed ending-range tuple moves monotonically: simulate a candidate → take the piece's √-argmax → re-simulate → repeat; then refine ± a few wei. See cl/active_set.rs. A profit-envelope gate (profit_envelope.rs) can reject the path before any walk runs.

Inside range 0 the CL pool is identical to a CP pool with virtual reserves R_in = L·2⁹⁶/√P, R_out = L·√P/2⁹⁶. Once a range exhausts, the curves diverge: the CL hop's marginal price jumps (liquidity changes) and eventually the pool empties at x = maxSpend — beyond that the swap reverts on-chain, which is why the solver clips the domain there.

Each section between dotted lines is one Möbius piece: one per ending tick range of the CL hop (deeper hops add their own shelves — V2 pools add one, V3 pools one per ending range — so a piece is an ending-range tuple k₁·k₂·k₃ over the V3 hops). The walk seeds an input, lands in a piece, jumps straight to that piece's √-formula argmax, and the landed tuple can only march one way — this tiny loop replaces combinatorial ending-range enumeration. The y-axis is symmetric-log: linear near zero so the peak stays readable, logarithmic tails so the deep-loss region and every walk step remain on-chart.
