# too_many_lines waiver census — the lint-waiver ratchet
# Gate body: scripts/hooks/too_many_lines_waivers.py
# Index: docs/gates.md section 6 "Lint-waiver census".
#
# What this file is. An expected `too_many_lines` lint is a deliberate decision to keep
# one function long. This census is the population of those decisions: one row per
# waiver site in the working tree, and the population only shrinks. A waiver with no row
# fails the gate (a new waiver cannot land silently), a row with no waiver fails (a split
# function deletes its row in the same change), and a missing census fails closed instead
# of passing over an empty population.
#
# Row format: "<repo-relative-path>::<scope>" and, when the site states one, a TAB then
# that reason verbatim from the source (a `reason = "..."` argument, or the trailing
# comment on the attribute), whitespace collapsed onto one line so the row survives a
# rewrap. There are no line numbers: a row has to survive every edit above it and vanish
# only when the waiver does. Rows are sorted.
#
# The scope names the annotated item — the identifier after the declaration keyword
# (`fn`, `mod`, `struct`, `impl`, ...) — and `!module` marks an inner `#![expect(...)]`,
# which waives the lint for the whole file. Two same-named items in one file (the nested
# walk helpers in the executor's grammar plan are the only case today) carry an
# occurrence suffix: `::walk`, `::walk#2`.
#
# The reason column is the point of the file. A waiver that states its reason must have
# that reason recorded here, and a row whose reason the source no longer states fails:
# the census mirrors the source and never improves on it. The two cannot drift apart,
# and a waiver's justification sits one file away from the code that carries it.
#
# The ceiling, "# reasonless-high-water: 100", freezes the count of waiver sites that
# state no reason at all: still a decision, but an unexplained one, and the first
# candidates for a split. That count moves only downward, so adding a reasonless waiver
# fails even when its row is added — a new waiver has to state a reason to land. Every
# shrink lowers the number in the same change.
#
# Regenerate the rows after a sweep (the header, the ceiling included, is by hand):
#   just check-too-many-lines-waivers --rows
#
# Blind spots, by design:
#   - the `allow(...)` spelling of the same waiver is out of scope: the workspace denies
#     that attribute at the lint root, so the expectation form is the only live one.
#   - a waiver that lands inside a macro expansion is invisible to a source scan.
#   - the ceiling is a reviewed baseline, not a proof: an author can widen it by editing
#     the number. That edit is exactly what the ratchet exists to put in a diff.
#
# reasonless-high-water: 100
#
