# Toolchain requirements for the `just` recipes ci.yml invokes by name.
#
# A recipe whose tool is absent from the job that runs it fails on the runner
# with a shell-level error (127, "no such command", "Failed to spawn") while
# every local gate stays green, because the developer environment has the tool.
# ci-parity reconciles this table against ci.yml in both directions: a recipe a
# job runs with no row here is drift, and a row no job runs is a stale claim.
#
#   recipe|requires|provides
#
# `requires` names the tools the recipe needs the environment to already have;
# `provides` names the ones the recipe installs itself. Each name is one
# provisioning predicate over the running job's own step text:
#
#   uv            an `astral-sh/setup-uv` step
#   cargo-nextest a `taiki-e/install-action` step installing nextest, or a
#                 `cargo install ... cargo-nextest` run
#   dev-venv      a `uv sync` run whose arguments include `--dev`, i.e. the
#                 lock's dev group (pyproject's vyper, maturin, and pytest pins)
#   llvm23        the `.github/actions/llvm23` composite, which supplies the LLVM
#                 23 that `llvm-sys` 231 links (docs/llvm-release-ci.md). Every
#                 recipe that compiles default features needs it: the Linux
#                 target scope pulls evm2-jit into both consumers.
#   foundry       a `foundry-rs/foundry-toolchain` install step, which supplies
#                 `forge` and `anvil` for the executor contract lane.
#   tier3-libs    a `tier3-oracle/bootstrap-libs.sh` run, which fetches the
#                 gitignored canonical Uniswap V2/V3/V4 sources the executor
#                 lane's Solidity artifact builder compiles.
#
# Read a recipe's body before adding a name here: `publish-dry-run`, for
# instance, is plain `python3` on purpose and needs neither uv nor the venv.
#
# The table models the tools that were historically provisioned inconsistently
# (uv, nextest, the dev venv, LLVM 23, Foundry, the tier-3 libs). A plain apt or
# npx need -- `fmt-check`'s cargo, `lint-markdown-check`'s npx,
# `lint-comment-hygiene`'s ripgrep -- declares no `requires` name, so an empty
# column is not a claim that the recipe has no dependency: read its body.
