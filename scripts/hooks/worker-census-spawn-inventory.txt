# Worker-census spawn-site inventory -- the reviewed exception list for
# scripts/hooks/worker_census_spawn_gate.py
# Index: docs/gates.md section 3 "Worker census".
#
# Rule: every `thread::Builder::new`, `Builder::new_multi_thread` or
# `Builder::new_current_thread` site under rust/crates must sit in a function
# that registers a WorkerCensusEntry (`worker_census::register`, directly or
# through a same-file helper that does), or be listed here under a written
# reason. One row per site, formatted "<repo-relative-path>:<function>" -- the
# file and the enclosing function are the unit the registration rule speaks
# about, so a row survives a line reflow.
#
# The reconciliation is bidirectional and fails closed: a site with no row
# fails, a row with no live site fails, a row with no `#` reason above it fails,
# and a missing file fails instead of certifying an empty census (an empty file
# is legal -- the tree's own sites still fail it one by one).
#
# Ratchet: a row is added ONLY with a reviewed reason for why the site cannot
# register at its spawn point, and it is deleted in the change that registers,
# moves or removes the site. `just check-worker-census-spawn --rows` prints the
# rows the tree does not hold yet, for review before they land.

# --- production spawners whose census row is registered a frame above them ---

# The offline fan-out probes build their own short-lived runtime through this
# helper. A probe binary installs no census exporter and dumps no boot table, so
# a row here would publish into a table nothing reads.
rust/crates/engine/degenbot-arbitrage/src/probe_support/dispatch_probe.rs:runtime

# The solver fleet's seat threads. Their census rows are the fleet role rows
# (`fleet_solver_slots` and the rest of the fleet set), registered by the
# dispatcher's fleet boot from `WorkerRole::census_resource()` and named from
# `role.thread_name()`; this boot spawns the seats behind those rows.
rust/crates/engine/degenbot-bot/src/arb_engine/fleet_solve_executor.rs:boot_seats

# The seat host's two bindings, the same role rows one frame above: the fleet
# boot registers them from the role descriptor, and both bindings name their
# threads from `desc.role.thread_name()` / `desc.host_thread`.
rust/crates/engine/degenbot-bot/src/arb_engine/seat_host/host.rs:boot_pinned
rust/crates/engine/degenbot-bot/src/arb_engine/seat_host/host.rs:boot_serial

# The scrape thread's row (`metrics_scrape`) is registered by
# `on_pipeline_started()` at pipeline boot, not by the spawner: the spawner is
# the injectable `ScrapeSpawner` fn pointer whose failing stub is the
# spawn-failure test seam, so the registration cannot ride it.
rust/crates/engine/degenbot-bot/src/metrics.rs:spawn_scrape_server

# A one-shot CLI arm's runtime: built, used and dropped inside one call by a
# command that boots no census dump, so no reader exists in that process shape.
rust/crates/shells/degenbot-cli-core/src/block.rs:block_on
